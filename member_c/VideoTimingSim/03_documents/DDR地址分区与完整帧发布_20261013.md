# DDR 地址分区与完整帧发布

> 2026-10-13 更正：后续集成以 [A 完整工程同步基线](../../IntegratedBaseline/a_sync_20261013/README.md) 为准。A 已完成异步采集、写入排空和结果发布；本文独立三源槽方案为候选扩展，其地址冲突不代表 A 当前基础版有缺陷。

本增量沿用已确认的 A/C DDR 分工，在 `1719db7` 的块写入适配上继续实现同一 UI 时钟下的采集事务管理。未更改 A/B 分支或现有板级 HDMI 程序。

## 统一地址表

`ddr_memory_layout.v` 根据源/结果尺寸计算三个源槽和两个结果槽，RGB888 存为 `0x00RRGGBB`，每像素占 4 字节。各槽步长向上对齐 32 字节。默认源 1920×1080、结果 640×904：

| 区域 | 字节基址 | A 的 32 位字基址 | 有效字节数 |
| --- | ---: | ---: | ---: |
| 源槽 0 | 0 | 0x0000000 | 8,294,400 |
| 源槽 1 | 8,294,400 | 0x01FA400 | 8,294,400 |
| 源槽 2 | 16,588,800 | 0x03F4800 | 8,294,400 |
| 结果槽 0 | 24,883,200 | 0x05EEC00 | 2,314,240 |
| 结果槽 1 | 27,197,440 | 0x067C000 | 2,314,240 |

末地址的排他上界为 29,511,680 字节，五个区域互不重叠。这是 C 的统一布局组件，**尚未迁移进 A 板级工程的全部消费者**。迁移时 A 的结果写入、结果显示、预读 `RESULT_BASE0/1` 必须同时使用表中的字地址，处理器的源读基址必须取锁定源槽的字地址，不能保留原来的结果基址 0x0100000/0x0200000 或固定源基址 0。

`MEMORY_BYTES` 默认 1 GiB，表示 28 位字地址接口的窗口上限，不是本轮实测的物理容量。集成时应改为板上实际可用 DDR 容量；不足、非正尺寸、超出接口范围或尺寸运算导致的巨大步长均令 `layout_valid=0`。无效布局不会接受新采集事务。A 固定版本 IP 文件中 `MEM_ROW_WIDTH=15`、`MEM_COLUMN_WIDTH=10`、`MEM_BANK_WIDTH=3`、`MEM_DQ_WIDTH=32`，此处仅核对源码配置，未重测实际芯片容量。

## 完整帧发布流程

`ddr_capture_session.v` 内部连接统一布局、`ddr_frame_slots` 与 `ddr_block_writer`：

1. `capture_start && capture_ready` 开始事务；分配可写源槽，等待块写入器开始。上游在 `block_ready` 前保留首块。
2. `block_valid && block_ready` 逐块接收；检测总块数、最后一块位置和准确字节掩码。源尺寸非 8 的倍数时也支持部分末块。例如 30 像素为 4 块，末块掩码为 `0x00ffffff`。
3. `source_done` 表示本事务的源帧验证已经结束，`source_ok=1` 才合格。源验证与 DDR 最后一个应答可按任意先后顺序到达；两个条件到齐前保持该槽占用，不发布。
4. 完成时 `capture_done` 脉冲与帧槽更新同拍；`capture_ok=1` 才发布新 `latest_frame_id`。读端锁定的旧源槽不会被覆盖。
5. 输入取消、源验证失败、异常块、内存故障或错误应答都会作废本帧。已接受的 DDR 命令必须排空后才能释放槽；发布同拍发生取消也不会发布。

`source_done` 必须来自本次采集的完整行宽/高度和后续边界验证，不能仅把预计最后一个像素当作最终验收。异常块不送入 DDR，事务按失败完成，生产端随后清掉属于这个事务的旧数据。

取消/内存错误可先结束 session，但跨时钟 RX 生产端和 FIFO 必须另外确认停止、丢弃旧 token，再允许新事务开始。这个模块没有跨时钟确认信号，不能单独把 `capture_ready` 当作 RX 已清空的证明。若上游源结束报告缺失，正常写完后会继续持有该槽，直到报告、取消或统一复位。

本模块的所有接口属于 UI 时钟域。`source_done/source_ok/capture_abort` 不能直接接异步相机状态；复位必须与 DDR 引擎及关联 FIFO 一起处理。相机时钟停止需要独立常运行时钟检测，不能用已经停止的 RX 时钟自行检测。

## 本轮验证证据

- 首次空实现失败于全高清内存分区断言；事务管理空实现失败于布局/会话输出断言。实现后通过。
- 帧管理回归检查：默认全高清布局、对齐、容量不足、零尺寸、极端尺寸总和回绕、源结束与写应答两种先后、读锁、写完后取消、写事务排空、短帧、错误掩码、源失败、发布同拍取消、复位和空事务取消。
- 代码审查发现极端正尺寸使 64 位分区总和回绕的问题，先添加用例复现失败，再增加单槽步长上限检查；修正后用例通过，复核无剩余关键问题。
- 增强原 `tb_ddr_writer_a_engine`：原 35 像素/5 块的块写入测试保留；新 `USE_SESSION=1` 接入 packer → session/slots/writer → A 实际内存封装 RTL，两帧共 32 像素/4 块及真实封装超时均通过。
- A 基础引擎与连续预读副本分别重跑，最终均 0 错误、0 警告。固定来源仍是 `main-A/6b0b2e257efcfbb379d3f447403beb5ad08e0086`。预读参数默认关闭，此处不验证预读算法本身。

复现入口：`run_ddr_capture_session_check.do`；含 A 引擎的增强回归仍为 `run_ddr_block_writer_check.do`，设置 `MEMBER_A_ENGINE` 到固定 A 源文件。原始日志保存在 `04_results/capture_session_20261013/`，其中名字含 red 的日志记录预期失败过程。

本轮未做 PDS 构建、烧录或实际 DDR 吞吐测量；小尺寸集成仿真不证明 1080p60 连续处理能力。下一步接入 A 已有 RX 采样/异步包 FIFO，将源完成、旧 token 清空和本模块的写事务排空统一管理，再迁移 A 所有地址消费者并验证三方争用。
