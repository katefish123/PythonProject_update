# C 到 B 源像素接口（2026-10-12）

用户确认沿用 A/DDR、B/算法、C/相机与视频接口的分工。本次新增独立适配模块 `hdmi_source_stream`，不修改已接受的相机顶层或板上程序。

## 输入和时钟合同

所有信号属于 RX 像素时钟域。`rgb/de/vs` 接已经寄存并对齐的输入，例如相机顶层中的 `rx_pixel_q/rx_de_q` 和 `recovered_vs`。`vs` 采用高有效帧同步，正边沿在垂直消隐期间；需要真实 VS 或已有恢复器提供 VS。不能把任意极性原始同步直接接入。

`link_valid` 是在此域同步的接收有效状态，低电平会停止输出并丢弃当前帧；恢复后等下一次 VS 正边沿重新开始。复位低有效，解除复位由集成方同步。RX 时钟停止时本模块不能自行检测失锁，独立时钟域的监测和 CDC 仍由系统集成负责。

`WIDTH/HEIGHT` 为有效源图尺寸，范围 1..4096，默认 1920x1080。输入一行的 DE 必须连续，中间空拍代表行结束，不支持任意行内空拍。

## 给 B/A 的输出

| 信号 | 含义 |
|---|---|
| src_valid | 当前输出为有效源像素，无 ready/背压 |
| src_rgb | RGB888，R 位于 23:16，G 位于 15:8，B 位于 7:0 |
| src_x/src_y | 有效区坐标，从 0,0 到 WIDTH-1,HEIGHT-1，不包括消隐 |
| src_frame_start | 和首个有效像素同拍 |
| src_frame_end | 和预期尺寸的末有效像素同拍 |
| frame_abort | 输入中断、短行、额外有效像素或未结束帧被新 VS 打断时的错误脉冲 |

输出相对输入寄存一级，RGB/坐标/valid/start/end 同步对齐。复位或重连后未等到 VS 的残帧不输出。

直接连接 B `b_rectifier` 的 `src_*` 同名端口，但处理时钟必须一致；若跨域，整组信号先通过 A 的 FIFO/CDC，不能只同步 valid。

`frame_abort` 不在 B 当前接口中。A 必须使该帧无效，不能作为完整 DDR 源帧发布。B 不得把中断帧的标记结果作为有效参数更新；后续集成需添加显式取消检测的机制，或复位受影响处理链再等完整帧。当前模块是流式传输，不缓存整帧，不能撤回已经送出的像素。`src_frame_end` 根据期望尺寸产生，若其后仍出现额外像素会再报告 abort；它不能单独代替整帧有效判定。

## A 和 B 下一步

- A：输入接完整源帧缓存；分配帧 ID/所有权；处理 abort、跨域和完整帧发布；按 B 的四邻域地址返回像素及标签/权重。可变延迟需目的帧缓存或输出 FIFO，不能直接固定延迟 HDMI 同步。
- B：沿用 main-B 的坐标/RGB/帧端口，确认源尺寸参数；配合恒等 H 和透视向量联调，后续处理取消检测合同。无需重写现有算法。
- C：保持相机直通基线；后续接入板级工程时验证恢复 VS、失锁监测和帧信号，之后再与 A 的输出缓存配合显示。

## 本次验证

采用 ModelSim SE-64 2020.4。先使用空实现观察到 FAIL_STREAM_COUNT，随后实现：

1. `run_source_stream_check.do`：8x4 与 1920x1080 两组，分别六个完整帧逐像素比较 RGB、x/y、首/末脉冲；含启动残帧、短行、中途 link_valid 丢失、重连残帧、帧中复位、提前新帧边界和恢复。两组 PASS，零错误零警告。
2. `run_source_marker_check.do`：连接 main-B `7fa2fa4` 中真实 `marker_detector` 和 `unsigned_div_seq`；两帧 32x24 RGB 四色方块，返回四组正确质心，两帧全部 PASS，零错误零警告。B 将 2.5 的质心四舍五入为 3，测试按其数值合同验证。

第二项复现前将 `MEMBER_B_RTL` 环境变量设为队友 final/rtl 目录。未复制或修改 B 源码。此测试不涉及 H 求解、DDR、整条矫正输出或硬件时序；新模块尚未 PDS 综合/上板。
