# 明日接线与验收

本包定位：A DDR + B R50/18mm 镜头全图试校正 + C 原生全高清采集/HDMI 输出的集成候选。输入、源帧、结果、HDMI 有效区均为 1920×1080、16:9。默认双线性镜头校正；不是自动纸框透视校正或框外保持的最终比赛版本。B 试标定仍为 `deploy_to_fpga=false`，没有改成正式标定。

## 接线和烧录

1. 相机保持 R50、镜头 18mm，HDMI 分辨率 1080p；相机 HDMI → FPGA 丝印 **HDMI IN/RX**。FPGA **HDMI OUT/TX** → VC-002Pro HDMI 输入，采集卡 USB → 电脑。根据实际丝印识别方向，不根据 A/D 字母猜测。
2. FPGA 电源接好并打开，JTAG 下载器排线按接头方向接板，下载器 USB 数据线直连电脑；采集卡 USB 和板上串口 USB 不能代替 JTAG。
3. 双击包内 `program.cmd`（或在终端执行 `program.ps1`），进行临时 CRAM 下载和回读。需要本机已安装 Python。脚本会检查全包、源码、时序报告、码流和 mask 的校验；失败则停止。每次保留独立日志。不会写 Flash，断电后需重新下载。
   完整性检查通过后，脚本会按官方手册启动同一安装目录的 `cdt_js.exe -port 65420`（若本机服务尚未启动）。若仍连接失败，查看本次 `program_logs` 内的服务日志，或通过 PDS Programmer 启动本机 JTAG Server 再重试。若链扫描找不到 PG2L100H，则核对板电源、JTAG 排线和下载器 USB，不跳过回读验证。仅执行 `python tools/program_package.py --check-only` 不启动服务、不访问硬件。
4. PDS 源工程入口为 `project/FullHD_Lens_RXRetimed.pds`。直接烧录不需要再次编译。需要修改源码时，修改后必须重新编译、最终时序检查和生成新资格，不能继续沿用本包码流。
5. OBS 选 VC-002Pro。烧录后若停留旧画面，先取消激活采集源再激活。画布源恢复为 1920×1080、保持比例、适配画布；不要把窗口缩放百分比当成源分辨率。

## 顺序验收

| 项目 | 操作和合格条件 | 必须保存 |
|---|---|---|
| 下载 | Program 与 Verify 均成功，目标 PG2L100H | 自动烧录日志及码流 SHA256 |
| 输出 | OBS 收到持续 HDMI 输出；诊断彩条只能证明输出有信号 | 初始状态/错误码 |
| 相机输入 | 相机处于短片取景且开机；等待输入切为有效画面，不能长期停留 INPUT/NO COMPLETE FRAME | 输入、接纳、拒绝计数 |
| RAW | 按住 KEY1，等完整帧/显示银行切换后出现 RAW；移动物体，画面持续变化 | 10 秒视频及显示帧 ID |
| 校正 | 松开 KEY1，等待 CORRECTED；物体移动后校正图持续更新，不是仅播放旧结果 | 校正发布、显示帧 ID 和更新间隔 |
| 全清 | 将文字、斜线、网格放在对焦平面，采集原始 1920×1080 图；与同场景 RAW 对照 | 两种原图，不能只保存缩小窗口截图 |
| 颜色 | 白纸、灰面、红绿蓝实物对照 RAW/校正，检查绿偏、灰雾、通道错序 | 同曝光同场景原图；诊断预览此前偏绿，未排除 |
| 模式/完整性 | RAW↔校正切换 5 次，无撕裂/旧帧冒出/银行代际错误；完整帧发布后才切换 | 计数、错误码 |
| 稳定 | 连续运行至少 10 分钟，无黑屏、DDR/PHY/自检错误、持续欠载 | 开始/结束计数和录像 |
| 重连 | 相机端 HDMI 断开再接回一次；重新出现真实画面、发布和显示 ID 继续推进 | 恢复时间及状态变化 |

HDMI 扫描为 60Hz；这不代表每秒生成 60 张新校正图。当前处理时钟约 57.1MHz，实际新校正图率需要通过发布/显示 ID 的时间变化测量。仿真两幅不同帧通过不能代替板上刷新率测量。

若仅显示彩条，先保存诊断状态和计数，不循环切换多个未知程序；若输入完整而 RAW 正常、校正异常，再查 DDR 读写、B 映射/插值和结果发布。若 RAW 也偏色，要先核对采集格式和 RX RGB，不通过调整锐化掩盖错误。

## 当前实际证据边界

独立 TX 时钟的取景诊断已收到相机实景，下降沿测得完整输入；该诊断为抽样预览，存在偏绿，不构成全高清光学验收。完整集成候选仍需按照本表上板。接线断开期间不能验证线缆电气质量、相机握手、实际 DDR 训练、颜色和真实帧率。
