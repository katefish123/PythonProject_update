# Independent synthetic RTL development, not an accepted board release

Extends the already documented lens_model_20261015 float/Q34.30 contract without modifying B, V5C or DDR/CDC/recovery interfaces. Real calibration is unavailable; Canon EOS R50 is a user-declared body only. This directory cannot qualify real optics or enterprise acceptance.

First numeric implementation is a sequential correctness baseline: a shared signed64 Q30 ALU,128-bit intermediate products, iterative signed nearest-even division; a complete validated pending/active parameter bank; an ideal-camera-pixel to raw-camera-pixel Brown mapping unit. This baseline deliberately does not claim1080p video throughput or final PDS timing. A later schedule/resource optimization must be measured and requalified.

Parameter words0..7:fx,fy,cx,cy,k1,k2,p1,p2 Q34.30;8..16:H row-major Q34.30;17:source width integer;18:height;19:profile version;20:H source frame id;21:camera mode id;22:provenance=1 synthetic only. All23 words required, dimensions/mode match runtime expectations, version/frame id nonzero32-bit. H range65536; focal1..65536; principal point in source; k1/k2 <=1, p1/p2 <=.25. Complete seal holds pending immutable. Frame-start commits the complete bundle. Seal coincident with boundary defers to next boundary; conflicting load controls reject. In-flight requests retain their captured parameters; no request acceptance on a frame-start edge. Real measured loading is not supported yet.

Runtime expectations are same-clock control inputs. The pending bundle is rechecked against them at commit. Active validity continuously checks dimensions and mode; a mismatch blocks new requests while already accepted transactions retain old metadata. Modes must identify all physical capture settings relevant to K; body name or dimensions alone are insufficient. Returning to the identical known mode may reuse a previously installed matching bundle.

Mapping core input is signed Q34.30 **undistorted ideal-camera** coordinate, not an old raw-corner H output. Each request captures lens parameters, dimensions, version/frame id and tag. Source bounds stay signed. Output coordinate/inside/numeric-invalid/tag must remain stable under response backpressure. Future correct composition requires raw-corner inverse undistortion and H fitting in that ideal domain, then this forward distortion and one final sampling stage. Capturing H in the bank alone does not implement that composition.

Implemented second baseline: lens_composed_map performs destination -> Q30 ideal-plane H -> Brown by snapshotting the complete request bundle before either stage. corner_preparation.py is a synthetic host-side damped Newton inverse and reuses the unchanged B float homography fit for ideal corners. Convergence/local positive Jacobian does not prove global inverse uniqueness; real measured operating-domain validity remains unqualified. Tests include projective H and all Brown terms simultaneously, matched raw corner preparation, and a wrong raw-H-before-Brown negative software control. No automatic black/white corner detector or real calibration estimator is added.

Verification uses pre-existing independent float and integer models, distinct nonzero coefficients, signed boundaries, large rejected normalized coordinates, zero-lens exact bypass, mismatch/reset/backpressure, complete-bank validation and frame commit. Coordinate RTL must match integer reference exactly on vectors; float differences and near-boundary behavior are reported separately. Pixel, inverse-corner/H composition, real calibration, full board integration and final implementation timing remain separate gates.
