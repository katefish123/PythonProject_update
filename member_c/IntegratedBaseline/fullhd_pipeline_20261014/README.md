# C：完整分辨率连续帧优化

本目录是独立开发候选。`main-C` 冻结在 `809c082504230350e3da9c30ac68a16cbd062a89`，用户回去烧录的文件未覆盖。

源图完整保留 1920×1080；B 校正结果为 640×904，HDMI 显示 1920×1080，保持结果比例。B 的八个算法 RTL 文件不修改。

## 为什么再改

原提前采集候选的小模型平均处理间隔改善 10.6%，但完整原生 DDR 引擎、算法、连续三帧及显示模型没有重现收益：串行平均间隔 18,674,496 个处理时钟，提前采集为 20,924,432 个，增加约 12.05%。提前采集第三帧在开始处理前已等待约 883ms。小模型结果不能作为完整系统的速度结论。

## 本轮改动

- DDR 原生适配器增加独立源图缓存，每块 64 像素，顺序扫描时突发读取。结果显示缓存保留；任意邻域访问不盲目突发读取，避免额外流量。
- 写入匹配缓存地址时失效，包括两个源图缓冲。尾部只用单拍读取，避免跨越帧边界。
- 后台采集推迟到当前结果完成 95% 时。门槛同时检查处理器 busy，避免上一帧残留进度误触发。首次采集和错误恢复仍可直接开始。
- 仅在采集请求仍未完成时启用三路争用保护；其他时间沿用显示优先的正常仲裁。原候选在没有采集时仍阻止处理器利用显示预取间隙，完整模型暴露了这项额外等待。
- 原串行、提前采集、此次改动使用相同原生存储延迟模型和同一输入序列比较。三帧输入交替改变灰度，逐像素验证结果和三代显示，禁止用重复旧画面冒充更新。

## 验证与复现

`prepare.py --output <输出目录>` 生成独立工程、全部输入哈希和 27 项测试。`run_verified.ps1 -OutputRoot <输出目录>` 在两个隔离工作目录执行仿真，要求零错误、零警告、PASS marker 和独立通过位。`measure.py --root <输出目录> --output <指标文件>` 汇总三种模式，检查新版本源图开始处理时的等待不超过 50ms、平均处理间隔小于串行基线、发布时最大图像年龄改善。

仿真资格通过后，使用上一轮 `a_sync_20261013/build_hires_reproduction.ps1`，指定 `-RequiredChecks 27`。必须以布局布线后的最终时序和烧录文件生成结果为准。打包脚本再次检查输入、仿真和构建证据哈希。

27 项完整回归已通过，零错误、零警告。每组连续三帧均核对 1,735,680 个校正像素及同数量显示像素。完整原生 DDR 模型结果见 [performance.json](performance.json)：

| 模式 | 平均开始处理间隔 | 开始处理时最大源图等待 | 发布时最大图像年龄 |
| --- | ---: | ---: | ---: |
| 串行冻结基线 | 691.648ms | 16.667ms | 677.077ms |
| 上一轮提前采集候选 | 774.979ms | 883.333ms | 1777.989ms |
| 此次预取＋延后采集＋仲裁窗口 | 599.984ms | 33.334ms | 645.135ms |

平均处理间隔相对串行减少 13.25%，相对提前采集候选减少 22.58%。原生 DDR 读取次数从串行 2,698,263 次降到 1,759,232 次。第三帧源图等待符合不超过 50ms 的门槛。

PDS 构建通过，布局布线及 hold 修复后的最终时序报告为 `All Constraints Met`。烧录文件、27 项仿真日志、输入清单、独立交替源图及输出参考、性能指标和构建日志均在 [release](release/package_manifest.json)。PDS 诊断保留在构建日志；仿真零警告不表示 PDS 零警告。

板上验收尚未执行。这些数值都是仿真模型结果，不能当作真实板上更新速度，也不能说明每秒校正 60 帧。完整源扫描、邻域读取和插值仍是后续瓶颈，详见 [NEXT.md](NEXT.md)。
