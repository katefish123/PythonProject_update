# 下次上板和最终交赛证据

你重新接好相机→FPGA HDMI IN/RX、FPGA HDMI OUT/TX→采集卡→电脑，以及板电源和JTAG后，再做以下验收。断线期间没有新的硬件访问。

1. 对匹配码流执行临时CRAM Program及Verify，保留日志。先证明真实输入和DDR训练/自检正常，再判断校正画质；诊断彩条不算完成。
2. 同一场景比较RAW和校正。固定18mm、对焦、曝光、机内镜头矫正、防抖等状态并记录；未经确认不能假定旧试标定仍适用。不要用锐化掩盖失焦或色序/范围错误。
3. 保留原生1920×1080图像和运动录像，不用缩小OBS窗口截图代替。黑/白/灰及RGB实物用于检查色偏和范围，文字/网格置于对焦平面。必须区分采集卡/软件显示转换、RAW链路和算法后的变化。
4. 记录实际发布和显示新图率、最小/中位/最大更新间隔、连续停顿、输入/接纳/拒绝/丢弃计数。源ID可跳号，跳过的ID不算已输出图。观察到的ID更新不证明传感器有同样数量的不同内容，还需运动场景对照。实际端到端延迟需同一时间基准或同步拍摄，不混减PROC/UI时钟。
5. 模式往返5次、连续至少10分钟、HDMI重连一次，保存开始/结束计数和恢复时间。不能把约0.5秒的模型样本代替这些实测。
6. 独立采集标定集和验证集，原始画面不可预先透视拉正/缩放。新标定原图应无诊断覆盖，可先相机直连采集卡采集并保持同一模式，再回板验证。图卡尺寸、固定镜头状态、原图SHA、估计方法/参数及独立采集组要留档，不能用同段视频留出帧代替独立复验。
7. 用独立棋盘/网格与斜边测试图卡测直线度和MTF50或SFR；当前几何工具仅完成前者的辅助测量。MTF/SFR报告、实际清晰度和真实标定仍待完成；不编造数值或把Laplacian方差冒充MTF50。可采用[MTF Mapper原项目](https://sourceforge.net/projects/mtfmapper/)等有测量方法说明的工具，并记录软件版本、图卡、曝光和单位。
8. 整理最终资源、时序、实测帧率/延迟、光学、长期稳定性和可复现工程。把用户要求的局部纸框校正/框外保持与所选动态演示单独列明；最新全图镜头候选尚未完成这些功能，不能用旧独立模块的仿真替代整板集成。

旧联调码流默认有大面积诊断覆盖。本次展示候选已通过独立控制测试：正常有效图默认干净；同时按住KEY1和KEY2稳定约50ms可切换诊断，切换在帧边界生效。双键期间原RAW/最近邻键义仍生效，松开后恢复默认双线性校正，诊断显示状态保留；再次双键关闭。约30次HDMI扫描没有新显示ID时保留HELD提示，故障提示优先，500ms仅是工程提示阈值，不是赛题性能门槛。须待这份新码流最终资格及实板通过，不沿用旧码流资格。

帧率低于60已由用户接受，但这不是对任意停顿、卡死、低清画面或其他缺项的豁免。达到哪些比赛基础/选定高级功能，以赛题与明确的用户需求分别说明，不擅自增加官方强制条件，也不遗漏既有要求。
