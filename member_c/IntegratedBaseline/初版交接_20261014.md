## 二、整合内容与配置

数据路径：相机 → HDMI RX → 完整源帧DDR → B角标检测及透视校正 → 结果DDR双银行 → HDMI TX → 采集卡 → OBS。

| 项目 | 当前配置 |
| --- | --- |
| 源图 | 1920×1080，每个有效像素保存，2,073,600像素 |
| 校正结果 | 640×904，578,560像素，固定竖向文档比例 |
| HDMI输出 | 1920×1080、60 Hz，校正结果居中，两侧留空 |
| 源像素格式 | RGB888，以RGB32字存储 |
| 发布规则 | 完整结果写入后切换显示银行；处理中显示上一张完整结果 |
| 算法更新方式 | 捕获快照 → 处理 → 发布 → 捕获下一帧 |

复用A固定提交 `6b0b2e257efcfbb379d3f447403beb5ad08e0086` 的整合工程，包括DDR IP、约束、采集存储、缓存与显示路径，也保留该基线中的C视频模块和B算法。

B透视坐标计算、透视变换和双线性插值算法未修改。本轮C覆盖的生产RTL共三处：上一版的 `video_correct_ddr_top.v` 与 `video_correct_ddr_core.v` 完成全像素采集配置、地址分区和角标阈值适配；本轮的 `frame_processor.v` 增加8项坐标描述符队列及读取衔接，减少等待。

640×904结果沿用项目文档比例，没有增加任意纸张长宽比自动识别。HDMI输出60 Hz表示显示扫描频率，不能作为每秒校正60张的证据。

- 17项ModelSim回归全部通过，零错误、零警告。
- 2,073,600个源像素通过实际采集/FIFO/写入器路径进入仿真内存，逐像素检查一致。
- 578,560个校正结果像素与固定B定点参考模型一致。
- 显示争用测试、异常采集、随机读取等待、长写停顿及处理中复位恢复均通过。
- PDS完整构建成功；最终时序为 `All Constraints Met`，码流已生成。
- 同一全高清模型处理周期：29,972,848 → 12,864,714，减少57.08%；按27 MHz约1.110秒 → 0.476秒。这不包含完整采集与显示切换，也不是板上实测更新速度。

发布包保留27个文件的SHA256、源码清单、构建日志与仿真日志。PDS诊断仍保留在构建日志中；仿真零警告不表示PDS零警告。`hardware_accepted=false`。

A旧基础a4版的HDMI校正显示已有历史实测记录。A高清候选版采用960×540源图；旧版本板测证据不能替代当前全高清提速版验收。
