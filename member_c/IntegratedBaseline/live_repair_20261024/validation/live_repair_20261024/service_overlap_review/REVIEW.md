# Independent overlap writer review

Reviewed frozen writer SHA256 `3c2a41136b9729a7a19df52158bfa5e942b0cf677a2bf0a1e035e04fd5f94ff0` and frozen contract bench SHA256 `af4e37d041270569a26533f8dcbe4c0df7d0471bfd547cfdb8608af7ba754212`. No production/candidate source was edited by this reviewer.

No blocking RTL defect found in this review. Normal collection writes a slot only while its occupied bit is zero. Retirement requires an issued/owned slot. Therefore simultaneous enqueue and ACK target different occupied bits; frame_bad collection does not write assembly. Each completed assembly flips fill_slot, and each retired assembly flips issue_slot. Once all full slots drain, both pointers agree, including after a partial bad frame. END consumption requires occupied==0 and !inflight, then clears partial fill. Thus frame terminal checks see all completed write ACKs and the correct written count. The command payload stays owned and stable during command backpressure and throughout one in-flight transaction. Common reset clears both slots, ownership, frame metadata, and the input elastic record. Unexpected responses with no issue/inflight remain ignored, matching the old writer's behavior.

Production engine captures all 2048 payload bits at command acceptance (`ddr_word_engine_result_burst.v`, accept_command). Its successful response is generated only after the last native WREADY beat with expected ID/LAST. The standalone writer bench's service counter retires eight separate modeled native beats during its final eight service cycles, then asserts ACK. This is a valid writer client contract test, not an integrated native DDR engine data test. Its 20-cycle/one-packet-per-three-cycle result demonstrates that overlapping collection removes a writer serialization cost. The same test with 40-cycle service correctly fails for both versions because the demanded rate exceeds available service. It does not establish the board's service distribution or a shared display/capture throughput guarantee.
