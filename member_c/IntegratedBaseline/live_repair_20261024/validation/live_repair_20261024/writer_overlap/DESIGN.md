# Isolated capture-writer overlap experiment

This directory is an unintegrated experiment. The frozen `candidate_v2`, delivery,
production FIFO, engine, arbiters, B algorithm and physical constraints are not
modified. No PDS or hardware operation is performed by this experiment.

## Contract and implementation

The original external ports, eight 256-bit beats per command, word addresses and
one native transaction in flight are retained. Two 2048-bit assembly slots replace
one. A completed slot becomes occupied and stays occupied through command stalls
and through the final write ACK. `issue_slot` advances only at retirement;
`fill_slot` advances only when eight valid packets complete a slot. Collection
requires its slot to be unoccupied. Thus an occupied payload cannot be modified.
Completion and enqueue on the same edge target different slots: enqueue observes
an unoccupied slot, while retirement owns an occupied slot.

The existing one-record input elastic stage is retained. END can be captured
there, but cannot be consumed until both full slots and the single inflight write
drain. The original seen/written counts, packet address/order, bank/generation,
END-good/reason checks and sticky fault remain. A partial bad assembly is discarded
at END; no partial command is emitted. Terminal backpressure preserves the frame
ownership and descriptor. No new frame replaces bank/generation before terminal
acceptance. Bad frames can drain already-owned full blocks, but cannot emit a good
terminal. A common reset discards all state and requires the existing coordinated
reset of writer/UI/engine; no independent soft abort or late-post-reset engine
response contract is introduced.

Pointers need not be reset between frames: every completed slot moves fill once
and every retired slot moves issue once. At drained END they are equal, including
odd block counts and discarded partial blocks. The lifecycle bench tests this
after malformed frames before a subsequent good bank/generation. Sticky fault
remains set across those frames as in the original writer; external protection
still owns the decision to recover the whole path.

## TDD and evidence

`old_red/step2.log` first demonstrated bounded queue overflow with the old writer
before the overlap RTL was written. Final immutable run directories below bind
their actual RTL, bench, command arguments, exit codes and logs. The uniform
16-slot queue is a **test producer model**, identical for old and new, not a new
production FIFO. The real source FIFO is unchanged.

| Final run | Expected result / coverage |
|---|---|
| old_red_final | 20 service cycles, 1 packet/3 cycles: bounded queue overflow |
| new_green_final | Same stimulus: 128 commands/ACKs, 1024 model native beats |
| old_limit_final / new_limit_final | 40 cycles at same input: both overflow |
| rate_old_final | 50 cycles, 1 packet/7 cycles: overflow at cycle1190 |
| rate_new_final | Same stimulus: 128 ACKs, peak1, final ACK wait47 |

| control3_final2 | Wrong response write flag: sticky fault/reason14, no good terminal |
| multi_final2 | Three frames, alternating source banks/generations, 384 ACKs |
| reset_final2 | Common reset while a write is inflight, then a complete new frame |
| lifecycle_final | Two owned slots when malformed control arrives; END waits both; odd slot parity/partial bad frame followed by a good new bank/gen; enqueue+retire same edge |

All nine final positive runs compile and simulate with zero errors/warnings.
The four bounded-overflow negatives intentionally Fatal, and are not counted as
zero-error simulations. Historical prototype directories are preserved; in
particular `control1` failed a **coverage** assertion because a rejected last DATA
never creates a last native burst. Its functional reject assertion had passed.
The final bench scopes the last-ACK-delay coverage to frames which actually have
a final full burst, keeping all functional and no-early-terminal assertions.

The small bench models a writer-client ACK only after eight tail service cycles
have retired; it checks all 64 ordered 32-bit pixel words at command acceptance.
It is not an actual engine/PHY/DRAM beat simulation. The engine's existing command
snapshot and last-WREADY retirement contract is assumed here and independently
reviewed. A separate integration control was run by the reviewing agent at
`D:/FPGA/output/live_repair_20261024/service_overlap_review/control` (not claimed
as evidence generated by this unit runner).

## Performance and qualification boundaries

The 20-cycle example is intentionally abstract and faster than physical RX packet
arrival. The 50-cycle/7-cycle-packet case is closer: one 64-pixel block arrives
every56 UI cycles; overlap service has spare capacity, while the original serial
eight-packet regrouping removes that margin. Actual 148.5MHz RX relative to125MHz
UI produces a packet each6.734 UI cycles, so seven is about4% slower and does not
prove physical input service sufficiency. The sustained 40-cycle/3-cycle case is
deliberately infeasible and both versions must fail. The separate shared-service
320-cycle cluster is a known-limit workload, not a promised repair target.

Two assembly slots improve writer utilization by overlapping collection and ACK
wait. They cannot repair negative long-term engine/PHY bandwidth, RX geometry
errors or display deadlines under arbitrarily slow service. Actual board reject
reason and service distributions are required before choosing this repair.
The added 2048-bit storage, selection and control may change physical timing;
there is no timing, resource, whole-board, realtime or image-quality qualification
from these unit results. Integration requires independent review, full regressions,
fresh PDS qualification and authorized board acceptance.
