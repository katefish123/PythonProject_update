# Frame completion / publication guard

Continuation of the already approved single-source-sample pipeline. Keep V5C and its existing DDR writer/CDC unchanged. This guard is placed between region_sample pixel outputs and ddr_result_writer_burst64. Parameters fix canvas dimensions, matching the actual writer. Initial integration uses the native1920x1080 aligned64 canvas; reduced32x4 tests exercise faults. No small-image result is presented as full-HD evidence.

Start snapshots source frame/version/bank and a separately reserved result bank. Start requires the writer drained; zero IDs or a result bank equal to the currently displayed bank are rejected without writer start. The external owner must keep that result bank reserved through descriptor consumption and any downstream pending display selection. The guard does not implement the cross-clock HDMI bank selector/allocator.

After a one-cycle writer-start phase, only scene-valid,error-free pixels with matching source IDs and exact raster x/y and last marker may reach the writer. Flattened addresses are generated by the guard. Any bad pixel, soft abort or writer fault cancels the frame and aborts the writer's partial block; queued complete blocks remain owned until their existing acknowledgements drain. No failed frame may publish. Missing pixels cannot complete; explicit source abort is required to retire a truncated stream (no new watchdog policy).

`upstream_idle` must cover all mapper/sampler/source-memory transactions and held outputs, not just input-valid. Start and successful publication require upstream retirement too. In ABORT_DRAIN, stop issuing new upstream work and accept/discard late upstream outputs without writing; wait for BOTH upstream_idle and writer_drained before releasing ownership. No upstream reset is substituted for draining physical memory. A caller must not start next-frame work independently while cancellation is draining.

Only the exact expected number of accepted pixels followed by writer_drained and no fault permits a stable publish descriptor. The existing writer's drained accounts for outstanding native write responses, not merely queue acceptance. A result is not immediately shown: a later HDMI frame-boundary selector must consume this descriptor. Do not call a descriptor hardware display acceptance.

Source/output namespaces are distinct: source bank may numerically equal result bank. Displayed-result protection compares result bank with front-result bank only. Writer reset, UI reset, native engine reset and guard reset must be coordinated; no late response may survive reset. All reads/writes of this writer must be exclusively owned by the guard session. No uncoordinated abort/drain or allocator recovery is invented.

Tests first: instantiate the unchanged existing writer with asynchronous source/UI clocks and a behavioral native memory-response producer. Verify full native raster addresses and packed blocks, withhold final acknowledgement, pixel/metadata/last faults, incomplete/duplicate data, pending write abort/drain, result-bank protection, output backpressure and coordinated reset. Mutation controls must detect publishing before writes drain and ignoring scene/bank association.
