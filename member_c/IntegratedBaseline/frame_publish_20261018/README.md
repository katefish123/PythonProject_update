# 整帧写入完成与发布保护

`corrected_frame_guard.v` 新增独立整帧保护，复用原 `ddr_result_writer_burst64.v`，不修改 V5C、原 B、旧 DDR/CDC/恢复模块，不产生新烧录文件。

## 实现

- 启动时捕获源帧号、版本、source bank 和预留的 result bank，拒绝零帧号/版本及覆盖正在显示的结果 bank。
- 只允许有效场景、无错误、同源帧/版本/bank、严格逐行坐标和正确 last 标记的像素写入。写地址由本模块累计生成。
- 必须收齐整幅画布、上游所有请求与输出退休、原 writer 的所有突发写响应返回后，才给出完整结果描述符；发布背压期间保持元数据稳定。
- 错帧或取消会丢弃部分块。已排队完整块仍需等待写响应；迟到的上游像素只排空、不再写入。上下游均空闲后才释放 busy。
- 缺像素不会发布，源控制器须显式 abort 来终止不完整帧；没有新增自动超时策略。

这不是 HDMI 切屏器。外部仍须预留结果 bank，并在 HDMI 帧边界接收/提交描述符；上游停止新任务和正确提供 upstream_idle 也是必要集成条件。复位必须与 writer/UI/原生内存引擎协调，不能单独复位计数后接收旧响应。

## 已验证

ModelSim 三组通过，编译和仿真零错误、零警告。源 SHA、日志及四个故意错误对照归档在 `verification.json`、`evidence/synthetic_publication.zip`。

|测试|范围|结果|
|---|---|---|
|完整画布|1920×1080，实际原异步突发 writer＋行为内存响应器|2,073,600 像素、32,400 个块及 ACK；完整地址与每个打包 RGB 核对；只发布一次|
|控制与异常|32×4，原 writer|7 种独立像素错误、最后像素错误、截断、零 ID/版本、前台 bank 冲突、取消排空、坏 ACK、描述符等待时取消、协调复位；16 次失败均不发布|
|采样执行器连接|32×4，实际 region_sample、fast H/Brown、原 B 插值、原 writer；源读和原生写端均为行为模型|同样异常流程通过，迟到采样输出跨取消排空不会进入下一帧|

原生命令 ready 有确定性背压，检查整个命令/数据包稳定；完整画布覆盖 28,589 个背压周期。故意去掉写响应等待、scene 校验、源 bank 校验或取消时的上游排空等待，测试均按预期失败。

采样连接测试使用整数恒等映射，验证生命周期；非零镜头与 projective 的独立 1024 向量证据继续见 `../frame_region_20261017/sampling_verification.json`。**完整画布测试没有执行全画布组合映射，不能据此声称整个校正链路达到实时帧率。**

运行 `run_tests.ps1 -Suffix <新名> -Native` 复验完整画布；默认控制测试，`-Sampler` 复验实际采样执行器连接。路径见脚本。
