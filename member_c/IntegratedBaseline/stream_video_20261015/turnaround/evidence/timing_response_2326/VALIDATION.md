# Engine response timing candidate

The original v4k 2240 routed timing report has UI max slack -2.792 ns from engine/rsp_rdata[255:0]_3_ret_17 to core/selftest/passed (7 logic levels; logic 1.241 ns, route 9.055 ns). Root owns the selftest comparison pipeline change. The next two paths are cache/fill_tag[7] through cache address arithmetic and both arbiters to engine/rsp_source_block[1127] and [871], slack -2.442/-2.410 ns (10 levels; logic 2.289 ns, route 7.652 ns). The final response control net has fanout 2042 and route delay 2.720 ns. See v4k_ui_max3.rtr.txt and binding.json for exact names/report hash.

Only turnaround/ddr_word_engine_result_burst.v and its focused test were changed. The 2048-bit response copy register is removed. Native read data remains registered; source/result block and selected word come from the existing registered caches. Five registered response control bits select response kind and word. The last beat writes cache[7] on the same edge that enters ST_RSP, so the block includes the actual final beat without an extra response cycle. Failed burst responses and writes select zero. Legacy malformed single-beat reads still return the captured raw word with fault, preserving the existing tested API. Hard reset clears selectors before any uninitialized cache is exposed. No changes to writer, command ownership, epoch/bank ownership, arbitration, timeouts, or AXI capture/result/source command validation.

Fresh baseline: c_turnaround_regression_20261015_timing_baseline_2315, seven cases pass. Fresh candidate: c_turnaround_regression_20261015_timing_response_2326, seven cases pass, zero errors/warnings, with immutable before/after source hashes. The extended test alternates source/result hits for 24 consecutive UI response edges, checks every full-block beat and selected word, requires no new AR and no lost/bubbled response, and retains old-response/new-accept checks. Existing tests cover native AW/W same edge, stalls, burst last/ID checks, timeouts, source prefetch/invalidation, result cache, source block and result block legality, capture burst, faults, and hard reset.

An intermediate refactor incorrectly zeroed malformed single-beat read data; the legacy native protocol test caught it, and the implementation was corrected to preserve captured data plus fault. An initial new test issued a forced source block at non-64-aligned addresses; the engine correctly rejected it. The test now keeps forced source addresses 64-aligned and varies result cache word selection.

These are functional and protocol results. No new PDS result is available here, so this evidence does not establish timing closure or sustained system throughput. Root must generate and test the combined candidate, including its independent selftest change. The original 60-frame v4k system evidence binds the previous engine, not this refactor.
