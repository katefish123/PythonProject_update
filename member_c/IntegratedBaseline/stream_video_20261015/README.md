# C：提高实际校正分辨率与刷新速度

本目录是 `c-pipeline-next` 开发工作，不能据此替换板上版本。冻结的 main-C 交接版本没有修改，B 的原始算法文件没有修改。

## 已验证的 V2 候选

源图完整保留1920×1080。有效竖版校正图由640×904提高到765×1080，按整数像素保持原竖版比例，左右留黑边；DDR按768×1080存放，左1列、右2列是对齐填充。有效样本数由578560提高到826200，约增加42.8%。这不是把整幅图拉伸到1920宽，也不代表恢复了相机失焦时丢失的细节。

新的处理器把坐标计算、四邻域读取、B双线性插值、结果写回分开流水执行。空间缓存一次取得邻近块，跨时钟队列保留源银行及帧代号；软中止只丢弃旧代号结果，已经接受的写入必须全部确认后才能发布或复用银行。

- 四邻域缓存同一热命中测试：旧串行路径64组需512个UI周期，新路径需71周期。
- 不含采集/显示争用的完整原生DDR校正：三个独立源图，各829440个存储像素逐点匹配整数参考；双线性单次约15.38ms。
- 同时运行真实RX采集、角标检测、原生DDR和HDMI扫描：三帧共2488320个校正像素、同量HDMI显示像素核对一致。V2提前采集样本的发布间隔是38.226986ms、33.408027ms；仍没有达到60幅不同校正图/秒。
- 当前V2仿真绑定证据见 `evidence/v2/qualification.json`，包含源文件SHA、日志和明确限制。缓存、桥接、预览及原生整机均无仿真错误/警告。
- 实际Pango PLL模型验证54MHz处理时钟、148.5MHz像素时钟；这与板上时钟测量、实现时序合格是不同检查。

V1实现已完成生成，但时序未通过：UI最差-2.752ns、处理域-0.030ns、像素域-0.163ns。V2拆开长路径后，处理域+2.473ns、像素域+0.563ns，UI仍有-0.800ns未通过。因此这些sbit禁止交付烧录，`board_replacement_allowed` 保持false。下一修正将缓存未命中选择与无效化分成不同周期，保留热命中流水吞吐。

## 复现入口

`python prepare_board.py --output <全新输出目录>` 生成独立工程，依次复用本仓库固定的上游及原始B依赖。生成目录有原生DDR、真实采集和HDMI测试所需的全部RTL。

`fixtures/generate.py --baseline <生成目录>` 重建独立整数参考。它不读取HDL请求或输出作为答案。`integration/run_tests.ps1 -Baseline <生成目录>` 可把原生通路测试指向新生成的依赖。

`system_test/prepare_test.py --baseline <生成目录>` 生成整机测试绑定；`system_test/run_tests.ps1` 检查通过位、错误/警告和仿真前后文件SHA。`verify_candidate.py --root <生成目录>` 校验当前V2证据、实际工程输入和B文件原样保留。

当前本机V2输出：`D:/FPGA/output/c_stream_board_v2_20261015`。所有性能数字都是明示场景下的仿真测量，硬件验收状态仍为false。
