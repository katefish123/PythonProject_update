## 上游同步

2026-10-15 再次核对 GitHub：A 为 `256b5ea2b8bf4a559f19adfca7465161654b8226`，B 为 `4106f3babb65096927d365bbab55f070b90325e2`。固定的47个上游文件及 SHA256 见 [A 快照](../a_black_sync_20261014/README.md)。采用 A 保留的黑标接口和行读取修复，不采用已经撤下的整套提速发布。

A 保留版源图采样960×540；本候选源图仍完整1920×1080。四个检测ROI按源图映射，下界乘2，上界为 `2*max+1`，面积阈值乘4、跨度阈值乘2。结果维持640×904，在1920×1080 HDMI画面中居中显示，保持比例。

B 的9个算法 RTL 文件保持上游原字节，包含黑标检测、质心、单应矩阵求解、坐标变换和插值。本阶段另建 C 接入模块 `c_corner_rectifier`，改变角点输入位置，不改变 B 的数学运算或定点舍入规则。

## C 本轮改动

- 在实际进入源图采集器的有效像素旁路运行原 B 黑标检测器，包含首末像素。避免采集结束后再次从 DDR 扫描完整源图。
- 检测结果带请求标识和源缓冲编号。处理器只在同一次采集的 DDR 写入完成、几何结果同时到齐后接收该帧。完成事件额外等待两拍，再锁存独立同步的成功状态；独立事件位避免失败帧没有元数据时下一帧被漏掉。
- 两个源缓冲分别保存角点；新请求清除所选缓冲的旧资格。写入失败无需等待不存在的检测结果；未识别到角标也能完成失败握手。
- 对齐16个坐标队列额度。A 的显示行读取在不采集时保持连续命令；后台采集时响应先暂存、下一拍写入，让等待的采集写入有机会仲裁，避免全源图采集被显示流量阻塞。
