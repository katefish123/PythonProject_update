# 面向每秒60次完整校正的分阶段改进

保留 1920×1080 源图、640×904 校正结果、文档比例和 B 的定点运算结果。`833af36` 可烧录候选保留，不覆盖其源码或发布包。

## 第一阶段：采集内检测及帧绑定

在实际进入 DDR 采集的像素流旁路实例化原有角标检测器。检测只处理该快照的有效源像素，首末像素包含在内。输出携带采集请求 token 和源缓冲 bank，跨域数据保持至下一次请求，不在处理中被下一帧覆盖。

处理域分别保存两银行的检测结果。采集完成仅在 DDR 写入器完成和同 token、同 bank 的几何结果同时到齐时发布。失败帧正常完成失败握手，避免等待不存在的角标死锁。处理器在被选源帧的角点上调用原 B homography_solver 和 perspective_core，不再从 DDR 重新扫描源图。B 的算法文件保持原样；C 改变其组件接入方式，接口改动明确记录。

验证包括有效角点、缺色/过量/断帧、首末像素、不同 token 和 bank、跨域不同到达次序、复位、完整像素与原定点参考一致。整帧检测及处理性能用实际1920×1080输入测量。

## 第二阶段：像素处理流水线

扩展邻域缓存以同时保留上下两行的空间局部块，避免两行之间反复驱逐。用描述符及结果队列解耦坐标、邻域读取、插值和写入；使用明确容量信用、标签及末像素排空规则。内存带宽与有效像素吞吐分开测量。

## 第三阶段：处理时钟及持续吞吐验收

27MHz 生成578,560个结果像素的单周期下界为21.43ms，不能实现每帧16.67ms。流水线稳定后研究更高处理时钟，重新检查PLL、B算术路径、超时、跨域和最终PDS时序。连续多帧采集到发布间隔必须不超过16.67ms，不能用HDMI扫描频率代替算法吞吐。板测还需真实输入、移动目标、长时间运行和重连。

当前快照协议在下一次 VS 边沿结束采集，无法同时接收同一边沿的新请求。持续逐帧采集还需要提前准备下一缓冲或独立完成通知；处理时钟提升本身不能消除这段等待。

三个阶段必须逐步给出证据。完成第一阶段不等于已达到每秒60次校正。
