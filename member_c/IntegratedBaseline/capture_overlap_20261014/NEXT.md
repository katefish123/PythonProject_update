# 吞吐优化的下一步

本轮双源缓冲解决源帧所有权与采集等待，算法本身仍采用上一版27MHz处理时钟和逐像素内存服务。

可由当前代码直接确定的下界：完整源图2,073,600像素，即使检测扫描每周期接收一个像素，27MHz下也至少需要76.8毫秒；当前实际调度包含缓存读取与等待，会更长。640×904结果即使每周期产生一个坐标，27MHz下也需要约21.4毫秒。单靠双源缓冲不能达到每秒60次全图校正。

下一轮应分别测量源图扫描、坐标/四邻域读取、插值/写入三个阶段，而不是把单帧总周期全部归因于DDR。优先研究采集阶段与角标检测衔接、减少重复源图扫描，以及更多像素的读取与插值流水线；处理时钟提高必须同时验证PLL/约束、跨域、阶段超时和PDS最终时序，不能仅按时钟倍数推断实际收益。

B算法语义与定点参考结果继续作为一致性约束。任何提速都保留原生全源图、同一文档比例和逐像素参考比对；若要改变B接口或算法，应明确记录变更及影响，不能归为只改C调度。

当前仍需冻结版板测：真实DDR初始化、图像质量、更新间隔、持续运行和相机重连。候选版另行板测，两个版本的证据不能混用。
