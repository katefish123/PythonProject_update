# 逐帧校正延迟优化

用户要求改善校正画面更新慢。本轮保持完整1920×1080源图、640×904竖向结果和原插值算法；保留已发布的全高清基线。

瓶颈：原调度器把坐标管线、四邻域读取、插值和结果写入串行执行；即使缓存命中，源扫描和四邻域每笔读取也要经过单独发请求的空拍。

方案：为坐标请求预留8个信用，使用8项描述符队列容纳返回的坐标、四邻域地址、插值权重和标签。信用包含仍在B坐标管线里的请求，避免无背压输出溢出。内存仍最多一笔在途；仅在上一响应到达时允许下一请求握手，兼容随机背压。结果仍有序写入，完整提交后才发布。

验收：同一原生全高清图、同一参考模型和内存等待模式下，结果逐像素一致，处理周期低于24,000,000（旧版约29,972,848）；另验证长时间写背压、边界、复位后恢复和已有16项回归。完成PDS最终时序后才交付码流。

边界：此次优化减少单帧处理延迟，尚不引入连续采集多源缓冲，也不宣称实现实时60次/秒校正。未连接硬件时，板上效果与实际更新速度仍未验收。
