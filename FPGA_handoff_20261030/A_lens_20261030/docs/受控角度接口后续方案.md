## 可复用的板载通道

推荐使用开发板已有的 USB 转串口：电脑 → USB Type-C → 板载 CP2102 → FPGA。无需外接 IMU，也无需寻找扩展排针。

| 板卡和转换芯片 | PDF 第 43 页（39），2.1.3.2.5“串口” | MES2L676-100HP 底板集成 CP2102，USB 接口为 Type-C，可连接电脑通信 |

| 物理 BANK | PDF 第 33 页（29），核心板连接表 | C24 为 `L3_G3_22P`，B24 为 `L3_G3_22N`，均属于 BANK L3 |
| IO 电源 | PDF 第 21 页（17），电源功能表 | L3/L4/L5 的 IO 电源为 **3.3V**；因此这两个单端 UART 引脚应按 **LVCMOS33、VCCIO=3.3V** 实现 |

B24、C24 虽然分别带有差分对的 N/P 名称，这里是两根独立的单端 UART 信号，不能配置成差分接口。电脑接板载 CP2102 的 Type-C 口；JTAG 下载线和 HDMI 采集卡 USB 不能代替这条串口链路。

已只读核对冻结基线 `C:/D/FPGA/A_board_20261029/candidate_de_frame_guard_v2/sources/board_ddr.fdc`：该文件声明 144 个端口位置，**没有端口占用 B24 或 C24**；原生映射实际使用 142 个脚位，另两个原始同步输入已被裁剪。当前冻结顶层没有 UART 或 DVIO 控制实例。这些事实不代表串口已完成上板验证。

未来增加 UART 后应保留原有全部视频、DDR、时钟脚位及其电气属性，并把 B24/C24 作为两项明确新增 IO 单独核验。不能继续套用“全部 IO 必须与旧版 142 脚完全相同”的检查条件，也不能因此放宽原有 IO 检查。

## 首选实现：镜头去畸变与可控仿射

第一版控制只使用仿射矩阵，固定底行为 `[0,0,1]`：

```text
          [ a00 a01 a02 ]
H_affine =[ a10 a11 a12 ]
          [  0   0   1  ]

u = a00*x + a01*y + a02
v = a10*x + a11*y + a12
```

上位机提供旋转角、水平/垂直剪切、缩放与平移控件，计算六项定点系数后下发。用户希望看到的正向图像变换，应先在上位机求逆，转成算法需要的“输出 → 理想源”映射。旋转和剪切可围绕画面中心构造，并与已验证的镜头有效视野矩阵组合。默认系数采用已验证的镜头校正视野，不能因为新增控制而更换镜头标定参数。

此方案中的“倾斜”指仿射剪切产生的倾斜外观，不声称它能消除真实三维透视。无需识别棋盘、纸边或四角标记，也不会自动推断相机姿态。镜头畸变补偿继续由原有镜头模型承担。

固定底行允许后续采用较简单的仿射坐标计算路径，但是否真正替换原有映射电路，需要实现后的数值、吞吐和最终原生时序检查。本文不把预期资源节省或帧率当成已测结果。

## 参数接收与帧边界提交

建议后续采用 115200 波特率、8 数据位、无校验、1 停止位。UART 时序必须按实际输入时钟计算并测试；27MHz 下每 bit 约 234.375 个时钟，可使用分数分频或误差经验证的整数分频。RX 输入需要同步及起始位、停止位检查。

协议至少包含：同步头、版本、命令类型、长度、递增序号、六项 signed40/Q24 系数、CRC 和确认响应。帧格式与字节序实现前应形成明确约定。一个建议的最小控制流程为：

1. 上位机生成目标参数，检查数值范围和矩阵可逆性后发送完整数据包。
2. FPGA 收到完整且 CRC 正确的数据包后，写入影子参数缓存；短包、校验错误、非法命令或超时不影响当前参数。
3. 通过带握手的快照跨时钟机制把整组参数送入处理域；不能对 240 位参数逐位做独立双触发器同步。
4. 处理器在开始下一幅校正帧、且此前事务已按现有规则处理完毕时，一次性锁定全部六项参数。该校正帧内参数保持不变。
5. 每幅结果附带生效序号；串口确认返回“已接收”和“已在第几帧生效”的状态，避免只确认收包却无法判断画面是否采用新参数。

连续拖动控件时可合并尚未生效的中间设置，保留最新完整一组；不得覆盖正在使用的系数。复位清除半包、跨时钟握手和旧参数提交请求，并恢复已验证的默认镜头校正矩阵。图像越界按现有 `inside` 约定填黑，不能把正常边界误判为 DDR 故障。

离线验证至少覆盖坏包、截断包、连续包、序号与确认、接收过程中复位、跨时钟更新、帧内不撕裂、按键旁路切换，以及默认/旋转/剪切/缩放多组完整图像的逐像素核对。30 张新图每秒的目标需要对受控变换范围重新测量；输入输出口标注 30fps 不能代替实际新图更新率。

## 可选扩展：真实透视

若后续明确需要三维倾斜的投影补偿，可扩展协议，允许九项 H 或相机姿态参数，底行不再固定为 `[0,0,1]`。上位机需要清楚约定标定内参、旋转轴、角度正方向及矩阵方向；控制层仍按完整矩阵和源帧绑定、帧边界生效。

该扩展要额外检查透视分母、映射有效范围、缓存访问代价和最终时序。它不包含自动棋盘检测，也不意味着系统能自动估计实际相机姿态。当前不实施此扩展。

## JTAG 备选

本机 Fabric Debugger 资料说明 DVIO 可以通过嵌入 FPGA 的核驱动内部 ProbeOut，且提供 `dbg_dvio_set_output` 和 `dbg_dvio_commit_output` 命令；本机提取资料位于 `C:/D/FPGA/video_correct_integrated_20261008/tmp/pdfs/fabric_debugger_text.txt`，对应手册 PDF 第 82–83 页及第 103–104 页附近。

当前位流没有 DVIO 核，使用它同样需要修改设计、编译、验证和重新下载，不能直接通过现有下载器写任意内部寄存器。它适合作为开发调试备选，板载 USB-UART 更适合独立上位机控制。本方案未执行任何 JTAG、串口或硬件操作。
