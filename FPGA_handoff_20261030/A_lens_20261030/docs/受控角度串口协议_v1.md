# 受控角度串口协议 v1

本版已接入活动候选 `candidate_host_angle_v2_product_stage`，包括控制RTL、跨时钟整组参数传递、真实仿射和镜头运算及分块写回。本轮未打开串口、下载程序或操作硬件。板载CP2102、B24/C24和电压出处见同目录《受控角度接口后续方案.md》。

## 参数与矩阵方向

`rtl/lens_uart_control.v` 的配置接口为 `cfg_valid/cfg_ready`、`cfg_sequence[15:0]`、`cfg_affine[239:0]`。六项均为二进制补码 signed40/Q24，依次为 `a00,a01,a02,a10,a11,a12`；a00 位于总线 `[39:0]`，a12 位于 `[239:200]`。

矩阵把**目标像素映射到去畸变理想源平面**，底行为 `[0,0,1]`。它与之后的镜头畸变取样模型组合，不能解释成“原始相机像素到目标像素”的正向矩阵。

```text
u = a00*x + a01*y + a02
v = a10*x + a11*y + a12
```

## 线格式

UART 默认 115200、8N1、空闲高、低位先传。按实际 `CLOCK_HZ` 四舍五入分频；27MHz 默认每 bit 234 拍。接收端含两级同步、起始位中点复核和停止位检查。

命令固定为 38 字节：

| 字节偏移 | 内容 |
|---|---|
| 0、1 | `A5 5A` 同步头 |
| 2 | 版本 `01` |
| 3、4 | 序号 uint16，小端 |
| 5 | flags，必须为 `00` |
| 6..10 | a00，5 字节小端补码 |
| 11..15 | a01 |
| 16..20 | a02 |
| 21..25 | a10 |
| 26..30 | a11 |
| 31..35 | a12 |
| 36、37 | CRC16，小端 |

CRC 采用 **CRC-16/CCITT-FALSE**：poly=`0x1021`，init=`0xFFFF`，不反射，xorout=`0`。命令覆盖字节 2..35，共 34 字节，不包含同步头和 CRC。标准向量 `123456789` 的 CRC 为 `0x29B1`。

完整命令经过CRC、版本和flags检查，且控制器空闲时才发布配置。截断包在最后收到一个有效字节后的40个bit周期超时，清掉半包。错误包、busy包不ACK、不产生cfg，不改变已有配置；上位机据超时判断失败。矩阵可逆性、signed40范围、定点退化和全图取样覆盖由配套上位机工具检查。底层UART协议不额外执行矩阵求逆或数值许可判断，直接自行构造底层数据包不能获得这些工具层保证。

ACK 固定为 8 字节：

```text
A5 5A 81 seq_low seq_high 00 crc_low crc_high
```

ACK CRC 覆盖 `81 seq_low seq_high 00` 四个字节，CRC 算法相同。只有匹配的真实 `commit_valid/commit_sequence` 才会生成成功 ACK，接收完成或 cfg 握手均不会提前确认。

控制器一次只处理一笔事务。事务从有效命令接收后开始，持续到匹配 commit 后的 ACK 完整发出；期间新命令整包丢弃。必须采用发送一包、等待对应 ACK 后再发下一包的上位机流程。序号用于匹配，不做永久去重；ACK 丢失后的重发可能再次应用同一组参数，参数设置应保持幂等。

## 帧提交与跨时钟连接

UART 控制器的全部端口，包括 `cfg_ready` 与 `commit_valid/commit_sequence`，都属于 `clk` 域。默认该时钟为板上 27MHz 系统时钟。

1. `cfg_valid` 产生后持续保持，直到 `cfg_ready` 握手。240 位系数和序号在等待期间保持不变。
2. 当前处理域为92.8125MHz。`lens_parameter_mailbox`以稳定载荷、请求toggle、确认toggle传递整组参数。接收侧在下一幅校正帧开始时原子锁定六项参数，一帧内保持稳定。
3. `cfg_ready` 仅表示配置已安全接收。握手后控制器仍等待应用完成，不能在这一边沿假装结果已经生效。
4. 当前ACK的精确定义是：该组参数已被一幅真正开始处理的校正帧锁定。返回事件经toggle确认可靠送回27MHz域。ACK不表示这幅结果图已处理完成、DDR写入已退休或HDMI已经显示；这些状态仍由结果帧发布和显示帧ID检查。
5. 控制器忽略尚未消费 cfg 的提前 commit，以及不匹配序号的旧 commit；允许 `cfg_ready` 和对应 commit 在同一边沿出现，但集成层必须保证该事件确实代表实际提交。
6. 公共硬复位取消半包和待处理事务，并清除相关CDC握手。DDR/应用恢复不复位参数邮箱，待处理命令和最后一组参数仍保留；应用复位期间不能消费或确认命令，恢复后在实际新帧开始时重新锁定参数。

UART 不直接驱动视频参数，不修改正在处理的帧。确认序号应与结果帧诊断值相对应；串口 ACK 本身不证明镜头光学指标或实际硬件帧率合格。

## 上位机工具

工具：`C:/D/FPGA/A_lens_20261030/tools/send_lens_angle.py`。

默认围绕 1920×1080 画面中心旋转，正角度表示显示画面顺时针旋转。工具计算逆仿射，并默认加载本工程 `calibration/r50_18mm_hdmi_trial.json`。它复用本机冻结 B 参考中的 `brect.viewport.plan_viewport`，同时逐像素检查浮点与实际定点的完整镜头取样映射，必要时裁剪并等比放大，以使 2,073,600 个目标像素都有有效源图取样位置。这个保证绑定到指定试标定、当前矩阵和尺寸，不等于光学标定已经通过独立实拍验收。

```powershell
python C:/D/FPGA/A_lens_20261030/tools/send_lens_angle.py --dry-run --angle-deg 12 --zoom 1 --sequence 77 --output C:/D/FPGA/A_lens_20261030/verification/angle12.json
```

`--dry-run` 只导出 JSON 参数和同名 `.bin` 命令包，不导入 pyserial、不开 COM 口；不指定 `--port` 时也默认仅离线生成。JSON 保留当前请求矩阵、最终六项 Q24 系数、防黑裁剪结果、标定/参考代码哈希、期望 ACK 和实际是否访问串口的标记。

工具还会读取实际候选的十个镜头定点常数，与所选标定逐项核对。标定或尺寸不匹配时，实际发送会在导入串口库之前终止；离线规划仍可输出不兼容标记，用于准备下一次重新构建。该核对绑定源码，不会自行识别板卡当前加载了哪份程序。

小角度旋转接近逐行方向时，完整128×128块可能挤满源缓存。默认规划在这一区域使用至少1.2倍等比放大，以减少缓存重复读取并保留30帧处理余量；因此视野会相应缩小。裁剪仍在逆映射矩阵里合并，不增加第二次图像插值。零度和180度轴对齐画面使用逐行读取，不增加这项裁剪；JSON记录最低放大值和实际附加倍率。`--no-autocrop`显式模式不作完整覆盖或30帧保证。

`--base-matrix-json` 可另外组合一个已有仿射视野矩阵。默认情况下 B 的完整镜头覆盖规划本身已经加入所需的基础防黑裁剪；零度、zoom=1 的六项系数为 `[16668374,0,146376934,0,16668374,100663296]`，与当前镜头安全默认值一致。

`--no-autocrop` 明确允许边缘取样越界填黑，输出记录不会声称全图防黑。实际发送必须同时显式指定 `--port COMx` 并省略 `--dry-run`；此时才延迟导入既有 pyserial，发送命令并等待与序号、CRC 完全匹配的提交 ACK。本轮没有执行该分支。

参考运行依赖复用既有 `C:/D/FPGA/A_software_20261024/deps` 和 `reference/B_lens_v2/python`，未安装任何新依赖。改变角度、缩放、标定或输出尺寸后，必须重新规划和验证覆盖范围。

## 离线验证

`verification/check_uart_control.py` 通过 ModelSim 在线路级发送实际 UART 比特，并用独立串口采样器核对 ACK；黄金命令与 ACK 来自 Python 的 `binascii.crc_hqx`。覆盖 CRC 错、非法版本/flags、截断、坏停止位、背靠背 busy、cfg 反压保持、消费后等待提交、错误/提前提交、三次实际 commit ACK 和两种中途复位取消。测试不打开串口、不连接板卡。

`tools/check_control_pipeline.py`已联合验证实际115200串口、27/92.8125MHz参数邮箱、真实仿射/镜头计算、四幅图像共16,384个像素及16字节ACK，覆盖帧中等待、应用复位保留和公共复位取消。`tools/check_lens_video.py`进一步验证完整1080p的DDR写入、HDMI扫描和新帧间隔。离线证据以各自时间目录和源码哈希为准；最终原生物理时序及实际硬件更新率仍需对应版本分别验收。
