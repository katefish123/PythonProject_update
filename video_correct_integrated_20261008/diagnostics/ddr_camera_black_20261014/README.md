# 黑色角标 DDR 透视校正工程

本工程使用 B 队友 `main-B / 4106f3babb65096927d365bbab55f070b90325e2` 的黑标算法包，接入已有的 DDR 完整源帧、校正结果双缓存、高清行读取修复和 16 额度坐标预计算调度。独立源码位于本目录，不覆盖原 A/B/C 或已有发布。

输入 1920×1080 RGB888，采样源 960×540，生成 640×904 彩色校正结果，居中输出到 1920×1080 HDMI。处理时钟保持 27MHz。KEY0 复位；按住 KEY1 显示彩条；KEY2 在开始处理一帧时选择最近邻，松开使用双线性。没有完整有效结果时显示彩条，坏帧继续显示上一张完整结果。

## 黑标规则和适用范围

四个实心黑方块，每个 RGB 通道默认 0～64。四个搜索区域的全部黑像素分别求质心，按 TL/TR/BR/BL 求透视矩阵。这里没有连通域、黑块编码、自动旋转跟踪或镜头畸变校正。黑色文字、阴影、背景和黑边框进入搜索区域会干扰检测。不要把默认四象限或四个固定区域当作 0～360° 自由旋转支持。

每块命中像素数 16～4096，坐标跨度不超过128。标记中心定义校正的四个角；标记印在纸内时，只拉正标记中心围成的区域。四块必须完整可见，四角必须形成凸四边形并通过原 B 的定点几何约束。

`config.json` 的 `black` 和 `rois` 是本版可调设置。ROI 坐标属于 **960×540 的源采样图**，不是1920×1080 HDMI 坐标；输入每2像素采一个，1080p相机截图的坐标可除2定位。现有几何尺寸和面积/跨度参数保持固定，准备脚本拒绝不匹配的配置，防止软件与板级参数不一致。

初始 ROI 对应 `results/camera_target_1920x1080.png` 的四块位置，已通过包含黑色正文的合成场景。`results/roi_guide_960x540.png` 显示红色搜索框，红框只用于定位说明，**相机应拍摄不带红框的测试图**。拍显示器时，需让屏幕内容填满相机有效画面并核对实际角标位置；实物纸张则根据保存的真实截图重新配置。最终以实际图像检测结果为准。

## 本地入口

- `prepare.py`：校验旧版来源哈希，复制完整源文件，适配黑标检测器的 Pango 数组索引宽度，把阈值/ROI 从板顶传到算法，生成测试输入和位精确期望图。
- `verify.py`：17项 B Python模型、9项原生ModelSim算法测试、实际 RTL CSV 对比，以及完整 DDR 系统回归。只有真实通过位和成功标记均通过才接受。
- `build.py`：核对仿真和源码哈希后运行 PDS，最终要求 `All Constraints Met`，不操作开发板。
- `archive.py`：封存通过检查的下载文件、源码、测试证据和配置。
- `show_target.py`：打开黑标相机测试图，Esc退出，F11切换全屏。
- `rectify_image.py <图片>`：读取保存的1920×1080相机截图或960×540源图，输出ROI叠加图、角标统计和软件校正图，不把软件结果当成FPGA实拍验收。
- `results/ddr_camera_black.pds`：构建成功后生成的板级工程。

修改 `config.json` 后，按 `prepare.py → verify.py → build.py → archive.py` 重新生成；改 Python JSON 不会自动配置已经下载到芯片的程序。

## 实拍验收

接线为相机 → FPGA HDMI-IN，FPGA HDMI-OUT → 采集卡 → 电脑。下载入口只写临时 CRAM 并回读，未写 Flash；断电后重新下载。下载后观察完整纸页、文字/彩色图形和无缺行，录制移动、缺角、恢复等情形，并测量新结果更新率与延迟。

新版本还没有相机/开发板验收。上次工程记录的板卡状态为断电降温，当前温度未知；需要重新确认连接和可测试状态。旧四色行读取版实测0.85次/秒属于旧程序，不能赋给这版。黑标整帧仿真周期约0.456秒，是模拟内存环境下的结果，不能称为30/60fps实时校正。
