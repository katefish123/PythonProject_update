# DDR status-screen probe

This diagnostic build has its own top module, `video_correct_ddr_status_top`, and its own PDS project/output directory. It does not replace the released DDR top or bitstream and does not program the board. Its PDS source list points to the existing DDR3 IP, `constr/board_ddr.fdc`, generated PLLs, and algorithm/core sources. HDMI configuration uses the existing `rtl/hdmi/hdmi_config.v` with `TX_FIRST=1`; no diagnostic I2C fork is required.

The TX raster is generated by `ddr_status_video` from `pix_clk` and a reset synchronizer released by `rst_n`, both video/config PLL locks, and `hd_reset_n`. It does not wait for RX pixel clock, DDR lock, DDR initialization, or frame capture. The normal algorithm and DDR top-level path remain instantiated and run independently; the diagnostic TX always shows the probe raster so a failed RX or DDR path cannot blank the monitor.

The output timing is 1080p60: 2200 total pixels per line and 1125 total lines per frame, with 1920x1080 active video. The upper active area is eight vertical color bars: white, yellow, cyan, green, magenta, red, blue, black. A status strip overlays active-relative `x=128..1791`, `y=1040..1071`. Each of its 15 cells is 96x32 pixels with a 16-pixel black gap. Green means 1, red means 0. Each status bit crosses into the pixel clock through a three-register synchronizer; the complete 15-bit value is then latched at the TX frame boundary and held for the whole frame to prevent cells from showing different update times.

Cells run left to right and represent these vector bits:

| Cell | Bit | Signal | Green when |
|---:|---:|---|---|
| 1 | 14 | `ddr_lock` | DDR PLL lock is asserted |
| 2 | 13 | `ddr_ready` | DDR initialization is complete |
| 3 | 12 | `phy_fail` | PHY initialization failure is asserted |
| 4 | 11 | `align_error` | DDR alignment error is asserted |
| 5 | 10 | `self_pass` | DDR memory self-test passed |
| 6 | 9 | `self_fail` | DDR memory self-test failed |
| 7 | 8 | `engine_fault` | DDR command engine fault is asserted |
| 8 | 7 | `rx_done` | HDMI receiver setup completed |
| 9 | 6 | `tx_done` | HDMI transmitter setup completed |
| 10 | 5 | `ack_error` | HDMI I2C ACK error is asserted |
| 11 | 4 | `image_valid` | A complete processed frame is published |
| 12 | 3 | `working` | The frame processor is active |
| 13 | 2 | `frame_error` | The latest frame was rejected or failed |
| 14 | 1 | `input_wait` | The core is waiting for a usable input frame |
| 15 | 0 | `underrun` | The display prefetch reported an underrun |

Run `run_status_sim.ps1` to verify bars, all 15 cell colors, asynchronous status synchronization, frame-stable status latching, and the independent raster. `build_status_probe.ps1` runs that simulation first, then builds into `results/ddr_status_probe`; it has no JTAG/programming step. The simulation validates the status-video block with a reduced raster for speed; the full PDS build validates the board-level top and unchanged DDR/IP/constraint integration.

## Probe bitstreams and hardware observation

The first diagnostic build, used for the initial board check, is [video_correct_ddr_status_top.sbit](../../results/ddr_status_probe/generate_bitstream/video_correct_ddr_status_top.sbit), SHA-256 `4276E65E0C8A80C8DC487C1FE1F5475A85C30D60FF9A9AC8EF4E978DCF2091AD`. It predates frame-boundary status latching; use it to inspect steady DDR flags, not to interpret simultaneous changing status bits.

The frame-latched diagnostic build is [video_correct_ddr_status_top.sbit](../../results/ddr_status_probe_latched/generate_bitstream/video_correct_ddr_status_top.sbit), SHA-256 `F86B7ACD05BEDC4F944879B4EDAFAD519E85AD5D36BAC39968D2B9871D67B2B8`. Its PDS report says `All Constraints Met`; slow-corner slack is 2.038 ns for RX pixel, 2.065 ns for TX pixel, and 2.168 ns for DDR PHY sysclk. The board was physically observed with the initial bitstream: `ddr_lock=1`, `ddr_ready=1`, `self_pass=1`, `phy_fail=0`, `align_error=0`, `self_fail=0`, `engine_fault=0`, `rx_done=0`, `tx_done=1`, and `ack_error=1`. The receiver clock and active video were present at the input; RX setup had not completed. The final frame-latched image has been simulated and built, but not programmed to hardware.

Main BRAM and DDR prepare scripts use explicit release-top/HDMI source lists. Their `--check` option verifies source coverage without regenerating constraints or build Tcl, synthesizing, or touching either release bitstream.
