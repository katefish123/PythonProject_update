# 黑色角标提速版（2026-10-14）

本版基于已经上板出图的黑标版，保留960×540源图、640×904 RGB888双线性输出、27MHz处理时钟和完整结果双缓存。上一版发布及录像保持原样。

本轮17项Python模型、9项原生ModelSim算法及16项系统检查通过，PDS最终时序报告All Constraints Met，下载文件已生成。码流SHA256为`39574d43ef4605fc1953de32dab1bb520a2f46de0ddfa059cb7860333669777d`。用户因板卡中央发烫确认已断电，本版未下载、未实拍，当前实时温度未知。

改动为：只扫描四个黑标ROI；源像素缓存增加128组×2路的二级缓存（每行8个像素，两条热点缓存仍可一拍命中）；插值结果进入16额度FIFO，使下一像素读取与插值、写入重叠。所有额度在实际写入接受后归还，单笔源读、整帧写完后发布、无效帧保留旧画面的规则保持。

同一合成测试和内存模型下，整帧处理由12315382周期降到6393441周期，即约456.1ms→236.8ms（1.93倍）；源DDR读378528→39351。全部578560个RGB像素逐个匹配原定点参考。此数值不包含相机曝光、采集卡、OBS显示延迟，实际更新率和端到端延迟待动态实拍。

黑标阈值及ROI与上一版相同。固定ROI仍会受构图、黑色正文和背景影响，原录像的底部灰边、轻微歪斜尚待校准；本版不构成自由360度旋转或30/60fps实时处理验收。

新二级缓存使用8块DRM，整机资源16494 LUT、19002 FF、25 DRM、53 APM；27MHz处理域建立时间余量20.969ns，DDR 125MHz域1.758ns。时序通过依赖沿用的Pango PHY约束及暂定HDMI外部时序模型。时钟未加速，资源变化和DDR读减少不代表温度已降低，后续先检查散热与实时片上温度。

`prepare.py`只首次建立封存版快照，后续修改使用`refresh.py`重算源码闭包并清除旧资格。`add_checks.py`生成稀疏/整帧扫描对照场景和新增测试入口。`verify.py`运行17项Python、9项原生算法及16项系统检查；`build.py`仅在来源、测试输入和日志哈希一致时构建；`archive.py`仅在时序通过后封存。下载入口`program.ps1`只写CRAM并回读，不写Flash；断电后需重新下载。

`show_latency_target.py`显示每100ms变化的计数黑标目标，并保存单调时钟与UTC变化日志。可从记录的输出计数跳变测量可见更新间隔。OBS标称帧率、日志时刻与静态照片都不能直接当作FPGA端到端延迟；若要量化绝对延迟，应同时录像记录源计数和输出计数。
