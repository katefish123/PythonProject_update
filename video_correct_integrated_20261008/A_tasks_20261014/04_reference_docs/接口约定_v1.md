# FPGA 任意角度图像畸变矫正系统接口约定

**版本：** v1.0  
**日期：** 2026-10-05  
**状态：** 已根据成员 B、C 当前交付的 RTL 和模块说明确认；系统级 HDMI/缓存集成项见第 8 节。  
**范围：** B 的 `b_rectifier` 算法边界、A 的帧缓存响应边界、C 的 VTC/TPG 视频时序边界。

本文以代码端口和参数为准。B、C 资料中的模块均可独立仿真，但两份交付尚未组成包含 HDMI 收发器、板卡时钟和帧缓存的完整系统。

## 1. 已确认的数据格式与电气约定

| 项目 | v1 约定 | 依据/备注 |
|---|---|---|
| 像素格式 | RGB888，24 位；`[23:16]=R`、`[15:8]=G`、`[7:0]=B` | B 的 `b_rectifier` / 插值接口及 C 的 `rgb` |
| 坐标原点 | 有效画面左上角 `(0,0)`；x 向右、y 向下 | B 输入坐标合同；C 原始扫描计数含消隐偏移，接 B 前须减去有效区起点 |
| 算法方向 | 逆映射：目的坐标映射到源图采样坐标 | B `perspective_coord` |
| H 数值 | signed 40 位 Q16.24 | B `homography_solver` 输出 |
| 源坐标 | unsigned 20 位 UQ12.8，单位像素，低 8 位为小数 | B `perspective_coord` 输出 |
| 插值权重 | `fx/fy` 各 8 位；最近邻时为 0 | B `perspective_core` |
| 地址 | unsigned 24 位，单位为像素，`addr=y*SRC_W+x` | B `perspective_core`；RGB888 字节/字/DDR 地址转换由 A 的存储封装负责 |
| 时钟 | `b_rectifier` 的全部接口必须处于同一个 `clk` 域 | B RTL 注释；跨域由 A 处理 |
| 复位 | `rst_n` 低有效异步置位复位；系统解除复位时由 A 同步处理 | B、C RTL 均为低有效异步复位 |
| `valid` | 单拍有效标志，无 `ready`/背压端口 | B wrapper；每个已接受的目的请求都必须得到一次响应 |

## 2. B 算法顶层 `b_rectifier`

### 2.1 参数

| 参数 | RTL 默认值 | 说明 |
|---|---:|---|
| `SRC_W`, `SRC_H` | 640, 480 | 源帧有效尺寸；合法尺寸范围 2..4096 |
| `OUT_W`, `OUT_H` | 320, 452 | 矫正目的图尺寸；合法尺寸范围 2..4096 |
| `UPDATE_EVERY` | 5 | 成功检测到角点的更新尝试节拍参数，须 ≥1；首次有效检测即启动求解 |
| `MIN_PIXELS`, `MAX_PIXELS` | 16, 4096 | 每种标记颜色可接受的像素数闭区间 |
| `MAX_SPAN` | 128 | 每种颜色质心包围跨度上限 |
| `R_*`, `G_*`, `Y_*`, `B_*` | RTL 中定义 | 四种颜色 R/G/B 通道阈值，各 8 位、闭区间；可参数化覆盖 |

默认颜色对应红=左上、绿=右上、黄=右下、蓝=左下。B 文档建议源图 640×480、目的图 320×452；需按项目实测视频尺寸覆写参数，不能把该默认值当作 C 输出尺寸。

### 2.2 输入端口

| 端口 | 方向/位宽 | 合同 |
|---|---|---|
| `clk`, `rst_n` | 输入，各 1 | 算法时钟；低有效异步复位 |
| `src_valid` | 输入，1 | 当前拍的源 RGB 像素有效；仅有效图像区像素参与标记统计 |
| `src_frame_start`, `src_frame_end` | 输入，各 1 | 源帧开始/结束脉冲。可分别与首/末有效像素同拍，也可在相邻空拍；A 须为每个源帧提供一致的边界事件 |
| `src_x`, `src_y` | 输入，各 12 | 当前有效源像素坐标，范围由 `SRC_W/H` 决定，坐标从有效图像左上角 0 开始，不得直接使用含消隐的 VTC 计数 |
| `src_rgb` | 输入，24 | 当前源像素 RGB888；送标记检测，与缓存写入的数据应为同一帧、同一像素 |
| `dst_valid` | 输入，1 | 当前拍目的像素请求有效；连续拉高表示可每拍提交一笔请求；无背压 |
| `dst_frame_start` | 输入，1 | 目的帧开始事件；若有待提交 H，则在此事件原子提交，新 H 可供同拍第一笔有效目的请求使用 |
| `dst_x`, `dst_y` | 输入，各 12 | 当前目的像素坐标，范围 `[0,OUT_W-1] × [0,OUT_H-1]` |
| `nearest` | 输入，1 | 随请求采样：1 最近邻，0 双线性；须随请求/响应元数据保持一致 |
| `rsp_valid` | 输入，1 | A 返回一笔缓存响应，包括应填黑的越界/无效请求 |
| `rsp_inside` | 输入，1 | 与对应请求的 `req_inside` 一致；无效请求返回 0 |
| `rsp_tag` | 输入，24 | 原样返回该笔 `req_tag` |
| `rsp_fx`, `rsp_fy` | 输入，各 8 | 原样返回该笔请求的权重 |
| `p00`, `p10`, `p01`, `p11` | 输入，各 24 | 同一请求四邻域 RGB888：左上、右上、左下、右下；无效响应可全 0 |

### 2.3 输出端口

| 端口 | 方向/位宽 | 合同 |
|---|---|---|
| `corners_valid` | 输出，1 | 一帧四色质心计算完成脉冲；四边形是否合法由求解器检查 |
| `x0,y0` ... `x3,y3` | 输出，各 12 | 红、绿、黄、蓝质心整数坐标；下一次有效检测前保持 |
| `marker_reject` | 输出，1 | 标记检测/统计检查拒绝脉冲 |
| `marker_dropped` | 输出，1 | 前一次质心计算仍忙，当前帧末快照丢弃的脉冲；像素统计继续进行 |
| `solver_reject` | 输出，1 | 四边形或定点 H 包络检查失败脉冲 |
| `geometry_valid` | 输出，1 | 已提交过一套有效 H；首次提交前坐标请求输出黑像素 |
| `params_pending` | 输出，1 | 一套完整的新 H 等待目的帧边界提交 |
| `stale_frames` | 输出，16 | 上次 H 提交后经过的源帧数，饱和于 65535；提交时清零 |
| `req_valid` | 输出，1 | 坐标阶段完成一笔请求；包括需要填黑的位置 |
| `req_inside` | 输出，1 | 请求有有效几何且四邻域采样在源图边界内；只有此位为 1 才读缓存 |
| `req_error` | 输出，1 | 数学/数值坐标映射错误；普通图像越界只清 `req_inside`，不置此错误 |
| `req_tag` | 输出，24 | `{dst_y[11:0], dst_x[11:0]}`，A 必须随响应原样返回 |
| `addr00`, `addr10`, `addr01`, `addr11` | 输出，各 24 | 左上、右上、左下、右下地址，单位为像素；`req_inside=0` 时为 0 且禁止读取地址 0 |
| `req_fx`, `req_fy` | 输出，各 8 | 双线性源坐标小数部分；最近邻或无效请求为 0 |
| `out_valid` | 输出，1 | 一笔目的像素完成；即使该像素为黑色也有效 |
| `out_rgb` | 输出，24 | 矫正结果 RGB888 |
| `out_tag` | 输出，24 | 对应目的坐标标签，A 可据此写入目的帧缓存/正确位置 |

## 3. A 的缓存请求/响应合同

每个 `req_valid=1` 必须且只能对应一次 `rsp_valid=1`。B 没有请求接收确认或响应背压，因此 A 必须保证已发请求均被保存并完整返回。

1. 保存每笔请求的 `{req_inside,req_tag,req_fx,req_fy}`。`req_inside=1` 才按四个地址取数；`req_inside=0` 不访问存储器，生成 `rsp_inside=0`、RGB 全零的响应。
2. 响应中的四像素和元数据必须属于同一笔请求、同一源帧。最近邻的四个地址相同，A 可以只读一次并复制到四路。
3. v1 规定按请求顺序返回。若存储系统乱序，A 须在接 B 前重排；B 不做乱序恢复。
4. 一张目的帧的源读必须锁定同一完整源帧，避免帧撕裂。B 接口不携带源帧 ID，源帧选择由 A 管理。
5. B RTL/仿真使用的单拍四读口模型不能证明 DDR 随机访问能达到目标视频速率。实际设计须由 A 评估突发缓存、行缓存/分 bank、预计算目的帧或其他有明确供数延迟的结构。
6. RGB888 在内存中如何打包、实际 DDR 字节地址/突发长度、读延迟和目标吞吐由 A 的存储方案确定；换算后仍须正确映射到 B 的像素地址单位。

## 4. B 子模块数值和节拍摘要

| 模块 | 已确认接口/行为 |
|---|---|
| `marker_detector` | `clk/rst_n/pixel_valid/frame_start/end/pixel_x/y/rgb` 输入；输出四色 12 位质心、`corners_valid/frame_reject/frame_dropped/busy`；通道阈值与统计限值参数化 |
| `homography_solver` | `start`、四个 12 位角点输入；输出 `busy/done/error` 和 9 个 signed 40 位 Q16.24 H；busy=0 才接收 start；失败时保留原 H |
| `perspective_coord` | 每拍可接受请求；逆映射输出 20 位 UQ12.8 源坐标、错误、有效和标签；输入到请求输出为 22 个时钟间隔（E0 输入，E22 输出） |
| `bilinear_interp` | 三段寄存流水；`inside=0` 仍产生有效黑像素；RGB888 输入/输出并传递标签 |
| `perspective_core` | 坐标、边界判断、四邻域像素地址和插值器的组合边界；默认参数源尺寸 640×480 |
| `b_rectifier` | 检测→H 求解→双缓冲 H→目的帧边界原子提交→像素请求路径；所有接口同一 `clk` 域 |

在 B 合同给出的单级缓存示例中，输入目的请求后 E22 产生 `req_valid`，E23 返回缓存响应，E26 输出 RGB（响应后 3 个插值寄存级）。真实缓存延迟为 L 级时，A 须对齐并原样保存响应元数据；无论具体 L 值，每笔请求都要返回一次响应。此周期描述不包含 A 的排队/重排/帧缓存延迟。

## 5. C 视频时序与测试图案模块

C 当前交付的是逻辑 VTC、TPG 和 `video_top`，端口以成员 C 的 RTL 为准。

### 5.1 `video_top`

| 端口 | 方向/位宽 | 合同 |
|---|---|---|
| `clk` | 输入，1 | 像素位置计数时钟；本模块不产生此时钟 |
| `rst_n` | 输入，1 | 低有效异步复位 |
| `pattern_sel` | 输入，2 | `00` 彩条，`01` 纯色，`10` 四象限，`11` 保留/黑色 |
| `hsync`, `vsync`, `de` | 输出，各 1 | VTC 逻辑同步与有效区信号 |
| `rgb` | 输出，24 | TPG 产生的 RGB888；`de=0` 时为黑色 |

`h_cnt/v_cnt` 是顶层内部信号，VTC 输出到 TPG，不出现在 `video_top` 端口上。时序参数可覆写：水平 `H_SYNC/H_BACK/H_ACTIVE/H_FRONT`、垂直 `V_SYNC/V_BACK/V_ACTIVE/V_FRONT`、`HSYNC_ACTIVE/VSYNC_ACTIVE` 和 `SOLID_COLOR`。

### 5.2 `video_timing_vtc`

输入为 `clk/rst_n`。输出 `h_cnt/v_cnt` 各 12 位、`hsync/vsync/de` 各 1 位。计数范围分别为 `0..H_TOTAL-1`、`0..V_TOTAL-1`；行末时垂直计数加一。默认同步极性为高有效，可由参数设置。有效区起点是同步宽度加后沿，区间左闭右开。

### 5.3 `test_pattern_generator_tpg`

输入为 `h_cnt/v_cnt` 各 12 位、`de` 1 位和 `pattern_sel` 2 位；输出 `rgb` 24 位。`de=0` 或保留模式输出黑色。有效区内模式为四段红绿蓝白竖条、参数 `SOLID_COLOR` 纯色、左上红/右上绿/左下蓝/右下白四象限。

### 5.4 C 默认时序值

| 方向 | Sync | Back porch | Active | Front porch | Total |
|---|---:|---:|---:|---:|---:|
| 水平 | 44 | 148 | 1920 | 88 | 2200 |
| 垂直 | 5 | 36 | 1080 | 4 | 1125 |

因此默认 `h_cnt=0..2199`、`v_cnt=0..1124`，有效区 `h_cnt=192..2111` 且 `v_cnt=41..1120`，共 1920×1080 个位置。同步默认高有效。上述计数值本身不定义实际频率；只有外部 `clk` 频率合适时才对应常见 1080p60 时序。

## 6. 当前模块间的连接约定

以下映射用于 A 编写顶层时参考，未代表已经存在可运行的系统顶层：

| 数据流 | 建议的信号处理 |
|---|---|
| 输入有效视频 → B 标记检测/帧缓存 | 将输入有效区像素转换为零起始 `src_x/src_y`；`src_valid`、RGB、源帧起止与缓存写入对齐。C 当前 TPG 只能产生测试视频，不能接收外部 HDMI 输入。 |
| 输出扫描 → B 目的请求 | 目的图像窗口内生成 `dst_valid/dst_x/dst_y`；坐标须在 OUT 尺寸内。若 C 默认 1080p 扫描承载较小 OUT 图像，由 A/C 定义窗口位置、窗口外像素值和请求使能。 |
| B 请求 → A 缓存 | 只对 `req_valid && req_inside` 发起实际读；对有效但 `req_inside=0` 的请求合成黑色响应，仍返回 `rsp_valid`。 |
| A 响应 → B → 目的缓存/显示 | 标签、权重、inside 和四像素同步返回；使用 `out_tag` 将 `out_rgb` 放回目标坐标或按固定顺序输出，并与 C 的固定扫描时序解耦。 |
| 视频时序 | 若 `out_valid` 不能保证固定像素周期到达，不得只把 C 的 `hsync/vsync/de` 固定延迟后与其直连；采用目的帧缓存/输出 FIFO 或由 A 证明的固定延迟供数合同。 |

## 8. 系统联调前待定项（A/C 负责给出具体值或方案）

1. **真实输入链路**：HDMI 接收芯片/官方例程、输入像素时钟、RGB 色序、同步/有效信号、帧边界定义和支持的输入模式。目前 C 仓库只有测试图案源，没有 HDMI 输入端口。
2. **真实输出链路**：HDMI 发送芯片配置、时钟生成/PLL、输出时序约束及管脚。C 的 `video_top` 仅输出逻辑 RGB/HS/VS/DE。
3. **视频尺寸匹配**：B 默认 `SRC_W/H=640/480`、`OUT_W/H=320/452`；C 默认有效画面 1920×1080。最终源尺寸、目的纸面尺寸、显示模式和窗口位置须确定，并覆写参数或配置坐标转换。
4. **像素时钟与时钟域**：输入写缓存、B 处理、显示扫描时钟的关系；必要的 FIFO/CDC 结构和复位释放方式。
5. **缓存实现与吞吐**：存储器类型/时钟、像素打包、读延迟、每拍四邻域供数能力、读写仲裁、整帧/双帧管理、源帧锁定策略及目的帧显示策略。
6. **视频协议适配**：HDMI 接收有效区同步到 `src_frame_start/end` 与零起始坐标的规则；C VTC 输出窗口坐标如何生成 `dst_valid/dst_x/dst_y`；窗口外填充颜色。
7. **板卡约束/物理接口**：MES2L676-100HP 的官方例程、PLL/IP、I/O 管脚与电平标准、PDS 工程及最终时序约束。
