# DDR3 controller IP for the PG2L100H board

## Generated target

`rtl/memory/ddr3_ip` contains Pango HMIC_S DDR3 controller + PHY IP generated by PDS 2022.2-SP6.4 IP Generator for Logos2 **PG2L100H-6 FBG676**. The board has two XCCC256M16EP-EINAY x16 DDR3 devices in one x32 rank (8 Gbit total, 1 GiB). The configuration uses the compatible MT41K256M16 timing preset, 15 row bits, 3 bank bits, and 10 column bits. The 125 MHz differential reference is the board's U7 oscillator. The IP runs at 1000 MT/s (500 MHz DDR CK), below the board's 1066 MT/s rating.

The source IDF was used only as a parameter template. `scripts/prepare_ddr_ip.py` replaces the target part, package, speed grade, data width, geometry, clock/timing values, bank-slice assignments, and all 71 DDR package-ball locations from the board manual. The generated IDF and PDS project both identify PG2L100H-6 FBG676. The IP Generator completed with 0 errors; its 2 warnings only note that existing template files were left in place. The checked-in generation log is `rtl/memory/ddr3_ip/ip_generate.log`.

At 500 MHz DDR CK (`tCK=2 ns`), the controller timings use CK-cycle counts. `DDRC_T_FAW=26` gives 52 ns, exceeding the Micron MT41K256M16 x16 / 2KB-page 50 ns minimum; the Pango default formula used 45 ns and was too short. The generated IDF's `DDR3_CL=7` is the physical CAS latency. Pango's `DDR3_CL_VALUE=6` and wrapper `DDR3_CL=4'd6` are the encoded MR0 value for CL7, not a CL6 setting. Thus `tAA=7×2 ns=14 ns`, meeting the MT41K256M16 -125 `tAA(min)=13.75 ns`. `CWL=6` is Pango's supported DDR3-1066-bin choice for rates above 800 MT/s, giving 12 ns at this clock. Other selected minima are rounded up to CK cycles by Pango (RCD/RP 7, RAS 19, WR 8); RFC=150 (300 ns), RC=25 (50 ns), and REFI=3900 (7.8 μs).

The DDR pin list in the IDF and generated example FDC matches printed pages 21–23 of `reference/official/desktop_hardware_manual.pdf`. The official PG2L100H-FBG676 package table (Pango PK04001 V1.3, pages 21–23) confirms all four board DQS groups are in R4: J4/H4 = R4_G1, H7/G7 = R4_G0, B5/A5 = R4_G2, and C1/B1 = R4_G3. The associated DQ pins also reside in R4. The IP bank indices are ordered with the CA bank first: R5 is `BANK0` for CA/PLL reference, and R4 is `BANK1` for all four DQ groups, so `DQ*_BANK_NUM` must be 1. This follows Pango's UI logic, which registers the CA bank before DQ banks; PNR mapping also associates `i_dqs_bank[0]` with the R5 side. The generated example FDC currently marks ports with `PAP_IO_UNUSED TRUE` (76 such attributes), so it is **not a drop-in board constraints file**. Preserve the verified `PAP_IO_LOC` values, but integrate the DDR pin IO standards, bank/VREF setup, and clocks into the main project's reviewed constraints and remove unused markings for the connected DDR interface before implementation.

## User-side interface

The generated wrapper is `rtl/memory/ddr3_ip/ddr3_ip.v`; all AXI-like signals use `core_clk` and active-low `resetn`.

- The address width is 28 bits. It is a controller/DDR address, not a byte address. For this x32 configuration one address unit is one 4-byte DQ lane word. Convert a byte address with `axi_addr = byte_addr >> 2`.
- A data beat is 256 bits (32 bytes), with 32 byte strobes in `axi_wstrb`. The controller consumes/returns beats in chunks of eight address units; advance the controller address by 8 for the next contiguous 32-byte beat. For example, byte address 0 maps to controller address 0, and byte address 32 maps to controller address 8. Keep accesses aligned to 32-byte chunks for simple frame-buffer use.
- `axi_awlen`/`axi_arlen` encode the number of data beats minus one. A single 32-byte beat uses length 0. AW/AR address and sideband fields must remain stable while valid is asserted, until the corresponding `valid && ready` rising-edge handshake.
- There is no `axi_wvalid` input or `axi_rready` input in this Pango interface. After the AW handshake, each rising edge with `axi_wready=1` consumes exactly one presented `axi_wdata`/`axi_wstrb` beat. Keep the current beat stable until that event; for AWLEN=0, supply one beat. `axi_wusero_last` is the controller's last-beat indication and can be checked for a one-beat transfer.
- A read request is accepted on `axi_arvalid && axi_arready`. Each `axi_rvalid` rising-edge beat must be captured immediately because the interface has no backpressure. For ARLEN=0, capture one 256-bit `axi_rdata` beat and expect `axi_rlast=1` on that beat. Use a FIFO or equivalent buffering if the consumer can stall.
- Assign transaction IDs consistently and use `axi_wusero_id`/`axi_rid` to associate returned beats when requests can overlap. `axi_awuser_ap`/`axi_aruser_ap` are optional auto-precharge controls; leave them inactive for the initial adapter unless bank scheduling explicitly needs them.

The address width follows row + bank + column = 15 + 3 + 10 = 28 bits. The Pango HMIC_S guide describes the concatenated address as row at the most-significant side, bank in the middle, and column at the least-significant side. Its burst address equation advances by eight units for a BL8 payload. Do not pass a byte address directly to the IP.

## Clock, reset, and initialization

Buffer the board's differential 125 MHz U7 reference through the Logos2 differential input primitive and connect the resulting single-ended clock to `ref_clk`; the generated IP wrapper expects a single-ended input. The example design also has a separate free-running system clock for its board/test logic; it is not the DDR reference.

Hold `resetn` low while the input reference and generated PLLs settle, then release it synchronously in the `core_clk` domain. Keep user traffic disabled until `ddr_init_done` is high. This output means the controller/PHY initialization and calibration have completed; it is the gate for all frame-buffer reads and writes. Monitor `pll_lock`, `phy_pll_lock`, `gpll_lock`, `rst_gpll_lock`, `ddrphy_cpd_lock`, `dbg_ddrphy_init_fail`, and `align_error` during bring-up. The debug/calibration inputs should be tied to the inactive settings shown in the generated `example_design/rtl/test_ddr.v` unless the Pango guide's dynamic calibration procedure is intentionally implemented. The APB port is for optional controller register/power features; tie it to a benign inactive interface if unused, following the generated example and IP guide.

## Verification boundary

The preparation script validates the device/header, critical memory/timing settings, unique package locations, and generated wrappers. IP generation finished cleanly and produced the 32-bit interface and a PG2L100H-targeted PDS project. This establishes parameter generation and source availability; it does not establish full top-level timing closure, board-level signal integrity, PHY calibration on the physical board, or frame-buffer read/write acceptance. No bitstream was programmed to hardware.
