# 空顶层 v0.1（2026-10-05）

本版是 A 的逻辑集成骨架，采用 B 当前四色透视矫正接口。外部接口保持稳定时，B 可以在内部替换识别方法。

## 打开哪些文件

- PDS 工程：`pds/video_correct_top.pds`；顶层：`rtl/top/video_correct_top.v`。
- PDS：2022.2-SP6.4；器件 PG2L100H、-6、FBG676；综合引擎 Pango ADS。
- ModelSim：`sim/skeleton/run_modelsim.ps1`，默认使用本机 SE-64 2020.4。
- B 的接口原文：`reference/b_baseline/interfaces.md`。

## 现在接好了什么

```text
外部源像素 src_* ──> B：b_rectifier（真实算法）
外部目的坐标 dst_* ─>      │                 ↑
                         请求             响应
                          └─> A：frame_store_stub
                                （一拍返回黑像素）
                       B 输出 out_valid/rgb/tag
                                │
                      未来结果缓存/显示接入位置

C：video_top（VTC + TPG）──> preview_*（独立测试图预览）
```

本次复用 B 的真实算法，不用空算法冒充原接口。源像素和目的坐标由测试平台提供；未来由 HDMI 接收适配器和 A 的调度器提供。

`preview_*` 与算法输出是两条独立路径，尚未连接成矫正显示链路。预览使用占位消隐参数，不是标准 HDMI 模式。`out_*` 没有显示同步信号，不能直接接显示芯片。后续应经过结果帧缓存或有明确供数保证的输出缓冲，再接 C 的显示链路。

本顶层不是开发板引脚顶层：这些坐标、地址、标签端口是内部模块边界，不能逐个分配到封装引脚。真实 HDMI、DDR、PLL、复位同步、CDC、帧调度和输出缓存尚未实现。未生成烧录文件。

## 第一版接口约定

| 项目 | 约定 |
|---|---|
| 时钟 | 所有当前端口同属 `clk`；上游必须保证同步，实际跨域以后加入 |
| 复位 | `rst_n` 低有效；上板前由时钟域内复位组件同步释放 |
| 像素 | RGB888，R 在高 8 位、B 在低 8 位 |
| 源坐标 | `src_x/y` 为有效图像区坐标，左上角为 0，不含消隐 |
| 源帧 | `src_frame_start/end` 按 B 合同提供；当前未存入真正缓存 |
| 目的请求 | `dst_valid` 才发出一个请求；`dst_frame_start` 提交待更新参数 |
| 插值 | `nearest=1` 最近邻，0 双线性 |
| 缓存地址 | 24 位，单位是像素，不是 DDR 字节地址 |
| 缓存响应 | 每个请求返回一次，包括 inside=0 的填黑请求；标签和权重原样返回 |
| 背压 | B 无 ready；调度器应在发出 dst_valid 前预留容量 |
| 输出 | `out_valid/rgb/tag` 同笔对齐；tag 为 `{目的y,目的x}` |

默认尺寸沿用 B：源 640×480、目的 320×452，只是可修改的占位配置，并未确定相机输出模式或比赛指标。测试使用源 16×12、目的 8×6；测试时钟 10 ns 也不是板卡时钟依据。

`frame_store_stub` 不保存任何帧，也不访问地址。它用一拍寄存返回请求元数据，像素全为黑色。当收到 inside=1 的真实读取请求时，`missing_storage` 置位并保持到复位，提醒缓存尚未实现。没有有效几何参数时，B 本身会请求填黑；这也必须保持请求与响应数量一致。
