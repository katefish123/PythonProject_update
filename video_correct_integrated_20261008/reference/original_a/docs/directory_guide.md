# 正式项目目录使用指南

工程根目录：`C:\D\FPGA\video_correct_fpga`。更新日期：2026-10-01。

本指南中的文件名和子目录名是存放示例，不代表这些模块或文件已经创建。当前仅已建立基础目录及说明文档。

## docs：工程文档

放开发环境、模块清单、接口约定、测试结果、问题记录和阶段计划。A 维护整体资料，B/C 补充自己负责的部分。

已有文件：

- `development_environment.md`：硬件、工具版本、当前验证情况与待确认项。
- `directory_guide.md`：本目录指南。

后续可按需要增加：

- `module_inventory.md`：模块名、功能、负责人、源文件、仿真结果、接入状态。
- `interface_contract.md`：时钟、复位、像素位宽、地址位宽、有效信号、输出延迟。
- `test_log.md`：测试日期、工程版本、场景、预期、实际结果、证据路径。
- `issues.md`：问题现象、复现步骤、负责人、处理结果。

文档引用代码或图片时优先记录项目内相对路径。外部原始资料的位置可额外记录完整路径。

## rtl：正式硬件源代码

这里放用于实际 FPGA 设计的 Verilog/SystemVerilog 源代码。各子目录按功能划分，负责人可以共同修改和审核。

| 子目录 | 放什么 | 示例 | 主要协作人 |
| --- | --- | --- | --- |
| `rtl/top/` | 顶层模块、系统复位/控制、模块间连接 | `video_correct_top.v` | A |
| `rtl/common/` | 可复用的计数器、状态机、同步器、RAM/FIFO 封装 | `counter.v`、`ram_wrapper.v`、`fifo_wrapper.v` | A，B/C 配合 |
| `rtl/video/` | 视频时序、像素流整理、HDMI 配置控制、帧缓存控制、DDR 用户接口封装 | `video_timing.v`、`frame_buffer.v` | C/A |
| `rtl/algo/` | 坐标变换、坐标到像素地址转换、边界处理、插值 | `coordinate_transform.v`、`bilinear_interp.v` | B/A |

例如，可复用 RAM 的读写接口封装放 `common`；专门控制视频帧写入、读出的模块放 `video`；将变换后的图像坐标转换成像素地址的模块放 `algo`。

新模块纳入正式工程前，记录接口和仿真结果。testbench 的延时激励等测试代码放 `sim`。

## sim：仿真源代码与独立仿真工程

这里放正式模块的 testbench、参考输入/输出数据、ModelSim 工程文件、波形配置和仿真数据。

建议每个被测模块单独建立子目录，例如：

```text
sim/
└─ frame_buffer/
   ├─ tb_frame_buffer.v    测试激励和检查
   ├─ input.mem           测试数据（需要时）
   ├─ frame_buffer_sim.mpf
   ├─ wave.do             波形布局（按需要保存）
   ├─ work/               该仿真工程自己的编译库
   └─ vsim.wlf            该次仿真的波形数据
```

ModelSim 引用 `rtl` 中的正式设计源文件；testbench 位于自己的仿真目录。各工程单独使用自己的 `work` 库。

`work`、仿真日志、`vsim.wlf` 通常可通过重新编译和运行生成；testbench、测试数据和波形布局应保存。关键验收截图存到 `images`，结果记录在 `docs`。

当前 LED 和计数器练习仍在 `C:\D\FPGA\demo\Simulation`，无需搬入这里。

## constr：引脚与时序约束

放正式工程使用的引脚位置、IO 电平标准、时钟周期和相关时序约束。文件类型、语法和扩展名以实际 PDS 工程及对应开发板官方例程为准。

引脚和板载时钟先由 A/C 核实，再加入工作工程。仿真的 `#5` 等激励延时不会成为真实硬件的时钟约束。

## pds：PDS 工作工程

放正式 PDS 工程文件及其生成的编译、综合、布局布线结果和报告。建议后续将工程根目录设在该目录内，并确认源文件引用位置。

设计源文件引用 `rtl`，IP 引用 `ip`，约束引用 `constr`。PDS 综合引擎使用 Pango ADS，testbench 不加入综合设计源文件列表。

正式工程以核实过的官方 HDMI 例程为基础创建。如果例程的 IP 或脚本依赖特定目录，先保留其可运行结构，再逐步整理和验证路径。

工程文件和配置需要保存；构建缓存与临时结果通常可重新生成。正式工程尚未创建，当前这里只是预留目录。

## ip：工具生成的 IP

放通过 PDS 工具生成的 PLL、RAM、FIFO、DDR 控制器等 IP。每个 IP 建独立子目录，例如 `ip/video_pll/`、`ip/pixel_fifo/`。

保存工具生成的配置、必要 HDL/网表、仿真模型及依赖。按照该 IP 的要求将相关文件加入工程。

工具生成文件保留原有内部结构；自己编写的端口转换或控制封装放到 `rtl/common` 或 `rtl/video`。不要手工把生成文件拆散后失去配置和依赖。

## images：测试图片与展示图片

放算法测试图片、棋盘格、网格图、原图/矫正图、波形截图、资源/时序报告截图和接线照片。

文件增多后可建立 `test_patterns/`、`waveforms/`、`results/`、`hardware/` 子目录。建议名称包含日期、模块或场景，例如 `20261001_counter_reset_enable.png`。

ModelSim 的 `vsim.wlf` 是仿真数据，放 `sim`；用于验收的波形截图是图片，放这里。图像效果对比记录注明测试参数、工程版本或算法版本。

## reference：原始参考资料

放对应 MES2L676-100HP 的手册、原理图、官方例程压缩包/原始副本，以及需要对照的 IP 文档。

例如可按需要建立 `reference/board/`、`reference/hdmi_demo/`、`reference/ddr_demo/`。记录资料来源、版本和获取日期。

修改和调试在工作副本中进行，原始资料保留用于对照。

## release：已验证的演示版本

放可以复现和演示的版本包，每个版本一个目录，例如 `release/v0.1_hdmi_colorbar/`。

版本包包含可用 bitstream、运行说明、板卡与视频参数、已验证结果、已知限制，以及对应源代码快照或其明确位置。现场需要的接线图、参数文件和备用材料也可加入。

PDS 的绿色勾号只能证明相应流程完成。要记录实际验收范围：仅仿真通过、已上板，或 HDMI 显示正常等，避免把生成的临时文件当作已验收版本。

## backup：恢复用工程快照

放重要节点或大改动前的完整工作状态快照，名称例如 `20261001_project_skeleton.zip`。记录日期、用途、对应版本和验证情况。

快照保留工程配置、RTL、约束、testbench、IP 配置、必要依赖和文档。备份时排除历史 `backup`、历史 `release` 及可重新生成的构建/仿真缓存，避免递归复制和体积膨胀。

部分官方 IP 和脚本依赖相对路径，恢复测试时应确认依赖仍可找到。重要备份再复制一份到其他磁盘。

## A/B/C 日常使用约定

1. B/C 交付模块时，同时说明源文件、时钟/复位、输入输出、数据格式、延迟、测试方法与结果。
2. A 将模块登记在文档中，验证后加入 PDS 工作工程，并与相关负责人联调接口。
3. 项目内优先用相对路径引用源文件；打包后检查是否仍引用某个人电脑上的外部路径。
4. 阶段版本验证通过后整理到 `release`；重要改动前保存 `backup`。

这些约定用于安排工程资料和验证流程，不预先确定尚未核实的视频规格、板卡引脚或算法接口。
