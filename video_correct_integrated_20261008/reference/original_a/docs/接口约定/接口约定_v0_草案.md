## 1. 目的与适用范围

本文件用于提前统一三人项目中图像数据、坐标计算、缓存访问和视频时序的基本约定，降低后续模块对接时的返工风险。

系统总体数据流暂定如下：

```text
视频输入 → 帧缓存 → 输出坐标映射 → 四邻域像素读取 → 双线性插值 → 视频输出
```

其中：

- A 负责顶层工程、缓存与数据调度、时钟/复位、模块连接和验证；
- B 负责坐标变换、双线性插值、算法规则及其软件参考结果；
- C 负责 HDMI 视频链路、视频时序、像素格式和板卡相关资料。

## 4. 算法与坐标约定

### 4.1 坐标方向

处理采用**逆映射**思路：对每一个输出像素坐标 `(x_out, y_out)`，计算其在原始图像中的采样坐标 `(x_src, y_src)`。

```text
(x_out, y_out) → 坐标变换 → (x_src, y_src) → 读取原图像素 → 插值 → output_pixel
```

这样可以减少输出图像空洞，具体公式、变换矩阵和参数格式由 B 确认。

### 4.2 暂定字段

| 项目 | 暂定约定 | 状态 | 确认人 |
|---|---|---|---|
| 变换类型 | 旋转/透视变换/畸变矫正中的实际方案 | 待 B 说明 | B |
| 输入参数 | 角度、四点坐标或 3×3 变换矩阵 | 待 B 确认 | B |
| 坐标数值类型 | RTL 使用定点数；整数位和小数位待确认 | 待 B 确认 | B |
| 坐标取整 | 整数部分用于地址；小数部分用于插值权重 | 暂定 | B |
| 坐标越界 | 暂定输出黑色 `(0,0,0)` | 待 B 确认 | B |
| 参考输出 | Python/OpenCV 输出图片作为正确性基准 | 已约定 | B |

## 5. 四邻域像素与双线性插值约定

当 `(x_src, y_src)` 不是整数坐标时，缓存模块需提供以下四个相邻像素：

```text
p00 = pixel(floor(x_src),     floor(y_src))
p10 = pixel(floor(x_src) + 1, floor(y_src))
p01 = pixel(floor(x_src),     floor(y_src) + 1)
p11 = pixel(floor(x_src) + 1, floor(y_src) + 1)
```

| 项目 | 暂定约定 | 状态 | 确认人 |
|---|---|---|---|
| 四像素顺序 | `p00, p10, p01, p11` | 待 B 确认 | B |
| 小数权重 | `frac_x`、`frac_y` 来自源坐标的小数部分 | 待 B 确认 | B |
| 像素位宽 | 暂定每个颜色通道 8 bit | 待 C 确认 | C |
| 插值输出 | 暂定 RGB888 | 待 B/C 确认 | B/C |
| 有效信号 | 四像素和权重同周期有效；具体延迟由 B 说明 | 待 B 确认 | B |

## 6. 缓存与地址访问约定

1. 输入视频帧由 C 的视频输入链路写入帧缓存。
2. A 负责将 B 输出的源坐标转换为图像存储地址，并完成四邻域像素读取与数据有效控制。
3. 任意角度/透视变换可能访问非相邻位置，第一版默认按“整帧缓存”评估；具体 DDR/片上 RAM 方案待开发板资源和官方例程确认。
4. 地址生成的基本规则暂定为：

```text
addr = y × IMAGE_WIDTH + x
```

| 接口方向 | 数据/控制内容 | 主要负责人 |
|---|---|---|
| C → A | 原始像素流、像素时钟、有效/帧/行边界信号 | C |
| A → 缓存 | 写地址、写数据、写使能 | A |
| B → A | 输出坐标对应的源坐标及有效信号 | B |
| A → B | 四邻域像素、坐标小数部分或等价权重、有效信号 | A/B |
| B → C | 矫正后的像素流及其有效/边界信号 | A 负责顶层转交 |
